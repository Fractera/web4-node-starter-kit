## What is built
- `.claude/hooks/shadcn-skills.mjs`: `interface-design` is required for every interface file (was: three panel folders only); a Bash or
  PowerShell command that WRITES a `.tsx` of an interface area (sed -i, redirect, tee, cp/mv/rm, python/node writes, git checkout/restore/
  apply) is held the same way; reads pass. ✗ Found: 743-4's lines went into `components/node-state/` and `components/hosting/` — outside
  the old panel list — and through python in Bash, which the hook never saw.
- `.claude/hooks/interface-design-start.mjs` (SessionStart): one line of context naming the skills; silent where they are absent.
- Both installed in the core (`.claude/settings.json`) and in every element (`scripts/element-isolate.mjs`: the skills hook now on
  `Write|Edit|MultiEdit|Bash|PowerShell`, the start hook on `SessionStart`). Both templates already carry `interface-design`.

## How it is proven
1. Hook plane: `scripts/shadcn-skills-hook.test.mjs` — new cases: any `components/` folder asks `interface-design`; python writing a core
   `.tsx` without the skills → refused («правка через оболочку»); `sed -i` on an absolute path → refused; `cat … 2>/dev/null | grep` →
   allowed; a write with the three skills → allowed; a non-interface write → allowed. Negative control: the old cases still pass.
2. Live plane: on this node after its update, a shell write of a core `.tsx` in a session without the skills is refused, and an
   element's regenerated settings (`npm run elements:isolate`) carry both hooks.
