# 743-2 — the target updates itself

**Done when:** `npm run node:update` and the update button run a frozen stage 0 that fetches the fork and hands the whole update to the
TARGET's own `node-update.mjs`, run from a throwaway worktree outside the project, so no line of the old version's update logic runs.

## What is built
- `scripts/node-update-stage0.mjs` — FROZEN (D43, ≤ 60 lines, header «frozen: changed only by the owner's word», seal in
  `scripts/node-update-stage0.seal` checked by `check:stage0` in `prebuild`). It does only: refuse the same wrong starts as today
  (unknown args, an agent's session without `FRACTERA_BUILD_LOG`); `git worktree prune`; `git fetch --quiet origin`; nothing new → the
  same «done, nothing to update» record; else `git worktree add --detach <os.tmpdir()>/fractera-update-<sha8> origin/main`; if the
  target's `scripts/node-update.mjs` carries the line `// @handoff v1` → `node <wt>/scripts/node-update.mjs --root <node>` with the
  same env and stdio; else (a target older than 743, a rollback) → the node's own updater, and one line saying so; in `finally` the
  worktree is removed and pruned; the exit code passed through.
- `scripts/node-update.mjs`: `// @handoff v1`; `ROOT` from `--root` (default: its own folder, so a direct run works as today); every
  path, child script and `require` of the node's tree is resolved against `ROOT` AFTER the merge (children already are); the modules it
  loads at its start (`node-records`, `git-identity`, `build-failure`) come from its own folder — the target's — which is the point.
  A first log line: «обновляет версия <target sha8>».
- `scripts/node-update-run.mjs:13` and `package.json` `node:update` → stage 0 instead of `node-update.mjs`.
- `ANTI-PATTERNS.md:49` kept: the worktree is never inside the node's folder (the core build inside the update would compile it).

## How it is proven
1. **Canary plane, with a negative control:** a scratch fork with one commit on top of 743 whose `node-update.mjs` prints
   `CANARY-TARGET-UPDATER` on start; a node at 743 runs stage 0 (fake npm, as probe 1) → the canary is in its log. Negative control: the
   same node runs its own `scripts/node-update.mjs` directly → no canary. A target without `@handoff v1` (743^) → the old way, its line
   printed.
2. **Leftover plane:** after done, after failed (fake npm) and after `kill -9` of the target's updater mid-run, followed by the next
   stage 0: `git worktree list` has one entry and `<tmpdir>/fractera-update-*` is absent. Windows: the same in CI (743-6).
