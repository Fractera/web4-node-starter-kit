# 743-4 — know before touching

**Done when:** the target's updater dry-merges in a throwaway worktree before its backup and refuses a collision in seconds with the
files named and nothing touched, and the page shows that verdict before the person presses the button.

## What is built
- `scripts/node-update.mjs` — a stage `preflight` right after `fetch`, before `backup`: a worktree of HEAD outside the project
  (`<tmpdir>/fractera-dry-<sha8>`), the records set aside the same way `node-records.take` does, `git merge --no-commit --no-ff
  origin/main` with the machine's identity, the unmerged files read, the worktree removed. Conflicts only in the node's own files
  (`NODE_OWN`, the registry) → go on (the real merge resolves them as today); any other → `refused` with `conflicts: [...]`, no backup
  folder made. `--preflight` runs only this stage and prints a JSON verdict (`{ ok, behind, conflicts }`) without writing the state file.
  Works on git 2.37 (this Mac; `merge-tree --write-tree` needs 2.38).
- Stage 0 passes `--preflight` through to the target's updater (one more argument in its frozen list — added before the seal is set).
- The door `app/api/node/update/route.ts`: a `POST { action: "preflight" }` (click-driven, no timer) → stage 0 `--preflight` → the
  verdict; `components/node-state/origin-notice.client.tsx` asks it on the bar's open when the node is behind and shows one line under
  the button: «Обновление пройдёт» or «Обновление остановится на файлах: …» (texts through translations, `check:i18n`).
- The launch page: `scripts/dedicated-server/launch.mjs` `probe` runs stage 0 `--preflight` on the server (stage 0 uploaded as in
  743-5) when a node is there and behind; `components/hosting/server-launch-check.client.tsx:57` shows the verdict beside the strategy.

## How it is proven
1. **Updater plane, with a negative control:** `probes/dry-merge.sh` turned into the real stage: the clean fixture → passes and the
   update goes on; the hot fixture (`scripts/serve.mjs`) → `refused` at `preflight` in < 10 s, `logs/node-update/` has no new folder,
   HEAD and `git status` byte-equal before and after.
2. **Eye plane:** `npm run eyes` on «Активация выделенного сервера» with the test server before 743-5's press: the line «Обновление
   пройдёт» beside «Дальше: обновить», looked at; the console clean.
