**Done when:** every commit, merge or stash the node's code makes goes through one module and is signed «Fractera node
<node@fractera.invalid>», and a guard refuses any other identity literal.

## What is built
- `lib/deploy/git-identity.mjs` → the ONE source (keep the file, widen it): `MACHINE = { name, email }`, `machineArgs()` → `['-c',
  'user.name=…', '-c', 'user.email=…']`, `machineEnv()` → the four `GIT_*` variables, and a `.cjs` twin only if a CommonJS caller
  needs it (`require` of an `.mjs` is not possible — measure each caller first). D38: always, not «only when none» (`identityEnv` goes;

  shell side needs none because every committing call is node code. Measure that claim: list every `git commit|merge|stash|rebase` in
  `scripts/**/*.sh` first; any found → it reads the module (`node -p "…machineArgs().join(' ')"`), never a literal.
- `scripts/fresh-project.mjs:121-122` → `machineArgs()`.
- Guard `scripts/check-git-identity.mjs` in `prebuild`: (a) refuses a `user.email=`/`user.name=`/`GIT_*_EMAIL` literal outside the
  module (exceptions by file name with reasons: tests that build fixtures, the workshop tool); (b) refuses a file that spawns git with
  `commit|merge|stash|rebase|cherry-pick|revert` and does not import the module.

## How it is proven
1. **Guard plane, with a negative control:** the guard green on the tree; in a scratch copy, a planted `-c user.email=x@y` in
   `lib/web4-items/node-map.ts` → refused naming file and line; a planted `spawnSync('git', ['commit', …])` in a new file without the
   import → refused.
2. **Git plane:** the probe-1 fixture (no identity, `user.useConfigOnly`): `fresh-project.mjs`, the update's merge (`node-update.mjs`
   with a fake npm, as in probe 1 B) and `evolution.mjs`'s commit all succeed; `git log --format='%an <%ae>'` shows only the machine.
   Control for D38: the same with `user.email=owner@example.invalid` configured → the machine's commits still machine, a plain
   `git commit` by hand → the owner's.
