# 743-6 — the transition is tested, not only the destination

**Done when:** a test in CI updates a node built from an OLDER version to HEAD through stage 0 on three OS, and fails when the
handoff, the identity module or the preflight is removed; the four rules are written where the next session meets them.

## What is built
- `scripts/node-update.test.mjs` (grown from `probes/old-updater-bridge.sh` and `probes/dry-merge.sh`, in node so Windows runs it):
  fixtures in a temp folder — a bare fork at HEAD (+ a canary commit), a node at the previous release commit diverged as at install,
  empty HOME, `user.useConfigOnly`, a fake `npm` first in PATH (a named seam: the build stages are proven live, never here). Cases:
  (a) stage 0 → merge passes, canary printed, merge signed by the machine, ledger written, no worktree left;
  (b) the node's own updater directly → no canary (negative control of the handoff);
  (c) the hot fixture → refused at `preflight`, node untouched;
  (d) a target without `@handoff v1` → the old way, its line printed.
- `.github/workflows/three-os.yml`: one step `node scripts/node-update.test.mjs` on all three runners.
- `development-docs/ANTI-PATTERNS.md`, «All systems», four lines, each with the date and the measured case: a transition hung on an entry
  point (8f165354); an identity literal outside the module (the census); a fix to the updater that the old updater runs (probe 1); a
  worktree or copy of code inside the project (l. 49, now cited by stage 0).

## How it is proven
1. **Test plane:** the CI run of the pushed commit green on ubuntu, macos and windows (`gh run list -R Fractera/web4-node-starter-kit`).
2. **Mutation plane (negative controls), in a scratch branch, never pushed:** stage 0 calls the node's own updater → case (a) fails on the
   missing canary; `machineArgs()` returns `[]` → case (a) fails with «identity unknown»; the preflight stage removed → case (c) fails
   (a backup folder appears).
