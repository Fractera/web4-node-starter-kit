## What is built

- **A prototype's own set** — `prototypes/_pages/<id>/sections/`: `index.ts` (the same shape as `components/sections/index.ts`) and one
  folder per section (`index.tsx`, `markdown.ts`, `README.md`). `npm run prototype -- new` writes its empty `index.ts`. The prototype's
  page draws the element's set plus its own. A prototype adds sections, it never replaces one: its kind may not repeat a kind of the
  element (a new look of an existing section is a new kind).
- **The wiring is generated, never hand-kept:** `prototypes/_components/prototype-sections.ts` imports every prototype's set — written
  by `npm run prototype` (new, pin) and by the build (`node scripts/prototype.mjs index` in `prebuild`). The prototype route passes its
  set through `childRoute` → the content page → `PostBody` (one optional `moreSections`).
- **The pin** (`npm run design:pin -- <id>`): checks first, moves nothing on a refusal — every folder of the winner complete, no kind
  repeated, the losers' sections committed (git keeps them). Then the winner's folders move into `components/sections/` with their
  import and set lines; the losers' `sections/` leave the tree, their `prototype.json` names `sections` and `sectionsAt` (the commit
  that holds the code: `git show <hash>:<path>`); every prototype goes to `_archive/` with its record, tokens, `DESIGN.md`, words and
  shots — no code. It prints the element's sections no page names any more (the agent decides, nothing is deleted for it).
- **The guard of every set** — `scripts/check-sections.mjs`, `npm run check:sections`, in `prebuild`: every folder of
  `components/sections/` has its import and line in `index.ts` and every line has its folder (named by its kind), every folder has
  `index.tsx`, `markdown.ts` and `README.md`; the same for each prototype's set; a prototype's kind never repeats the element's.
- **The archive is history:** `check:page-sequence` and the migration (`check:words`) do not read `_archive/`; `check:page-sequence`
  gives a prototype's page its own set too; `stamp-widget-ids` covers a prototype's own sections.
- **The words:** `.claude/modes/build-design.md` (the order step 5, the pin), the READMEs of `components/sections/`, `prototypes/`,
  `_pages/`, `_components/`; `lib/prototypes.ts` comment; the tree manifest regenerated.

## Done when

A prototype's own section is drawn on its page and nowhere else; after the pin it is the element's section — drawn on the source page
and carried into its Markdown twin — while the loser's code is gone from the tree and readable from git; every guard is green, and each
spoiled set is refused by name.

2. **Behaviour** (a scratch copy built and started on a scratch port): two prototypes, `calm` with `section-hero-calm` and `bold` with

   prototypes sit in `_archive/` without code, `prebuild` green although the archived `bold` names `section-hero-bold`.
