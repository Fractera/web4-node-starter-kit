# 717-2 — the word «section» and a section as one folder (custom template)

Merged with the code part of 717-3 (my decision, told to the owner): both move the same files, so a section goes straight into its
final shape. 717-3 keeps the prototype's own sections and the guard of the set in both directions.

**Where:** the workshop clone `data/workshop/fractera-custom-item-starter` (from v0.3.185, branch main), pushed with its CI; no tag —
the release is 717-7.

## Built as a migration (the owner, ~15:05: «сделать скрипт который просто выполнится автоматически исправит все остальные элементы»)

- `scripts/migrate-sections.map.json` — the rename map as data (paths, imports, kinds, names, phrases): the document of every replacement.
- `scripts/migrate-sections.mjs` — `npm run migrate:sections` prints the plan and writes the report; `-- --apply` does it. It moves the
  files, splits each section into its folder (its component, its `markdown.ts` cut out of the old switch), renames the kinds in page data
  and the names in code, rewrites imports and the standard phrases; what it cannot judge — a «block» in a sentence of the element's own —
  goes into the report `development-docs/reports/migration-sections-<date>.md` with the line and the rule, for the element's agent.
- The template itself was migrated by this script from v0.3.185 (717-2a, `c8c1c72`); its own words and small renames were then made by
  hand (717-2b, `d1d8150`). **The split, as built:** the script carries what is the element's own — its sections into folders, the set,
  its page data (kinds, `blocks` → `body`), names and imports in its code, the dead file — and lists its own prose for its agent; the
  template-owned files (instruction, modes, skills, READMEs, guards, comments) reach an existing element by the template's rollout
  (`npm run template -- rollout custom <tag> <paths>`), as every template change does. The guard `check:words` is the script's `--check`.

## What is built

- `components/sections/` replaces `components/blocks/`: `index.ts` — the set (one line per section) and the type of a section item
  derived from it; `page-body.tsx` — the factory that draws a page's sequence; `README.md`; one folder per section, named by its kind —
  `section-head/`, `section-warning-card/`, `section-faq/` — each with `index.tsx` (the component and its `Shape`), `markdown.ts` (its
  machine copy) and `README.md`. The set's type makes a folder without `markdown.ts` fail to compile — no separate exhaustive switch.
- The kinds in page data: `block-section-head` → `section-head`, `block-warning-card` → `section-warning-card`, `block-faq` →
  `section-faq`, a first screen `block-hero-<name>` → `section-hero-<name>`.
- `lib/content/blocks/` and `lib/blocks/` are gone: `types.ts` → `lib/content/page-items.ts` (`PageItem` — sections, text and widgets;
  `Link`, `FaqPair`, `TocItem`), `links.ts` → `lib/content/links.ts`, `lib/blocks/inline.tsx` → `lib/content/inline.tsx`,
  `lib/blocks/tone.ts` → `lib/content/tone.ts`, `registry.tsx` → the set and `renderPage`; `lib/aio/blocks-to-markdown.ts` →
  `lib/aio/page-to-markdown.ts` (asks each section's own `markdown.ts`). The table of contents is not a page-data section: it moves next
  to its only user, `components/content-page/toc.tsx`.
- Found on the way: `lib/content/blocks/inline.tsx` is dead — a second `inline()` and `headingId`, imported by nobody since 280-2a
  (only a comment in `cookie-banner/types.ts` names it) — deleted.
- The words: every README, `CLAUDE.md`, `.claude/modes/*`, the skills, `development-docs/glossary.md`, guards' messages — «section» for a
  part of a page; «block» keeps one meaning, the address of a container (`data-block`, `#block=`, `bid`, `blocks:ids`, the highlight).
- A guard `check:words` in `prebuild`: refuses «block»/«блок» in the sense of a section in the template's code and documents; allowed —
  the address family above, a code block, CSS (`display: block`, `inline-block`), `blockquote`, vendored skills (`SOURCE.md`).

## Done when

A fresh clone builds, every guard is green, the four public document pages and the guest page draw the same HTML and Markdown as
v0.3.185 except the kind names, and the word «block» stands only where it means an address.

## Proof — two planes, named before the work

0. **The script against a fresh clone of v0.3.185:** `--apply`, then the diff against the hand-finished workshop shows only the lines its
   report lists for the agent's eye — nothing it claims to do is left undone, nothing is done that it did not list.

1. **Machine, with a negative control:** `npm run prebuild`, `tsc --noEmit` and `next build` pass; then spoiled on purpose — a page JSON
   names `block-faq`, a README says «the blocks of this page», a section folder loses its `markdown.ts` — `check:words`,
   `check:page-sequence` and `tsc` refuse each; restored — green again.
2. **Behaviour:** the build started on a scratch port; `/en/privacy`, `/ru/terms`, `/en/cookies` and `/en/guest` (and their Markdown
   twins) fetched before (v0.3.185 build) and after; the diff shows only `data-kind` values and nothing else.
