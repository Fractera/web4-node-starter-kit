# 749-3 — «Адрес в интернете» tells the truth on a dedicated server

## Built
- `lib/domain/reach-road.mjs` — `roadOf(domain, place)`, one pure choice: `tunnel` (zone + `tunnelId`), `server` (zone + `via: "server"`),
  `server-no-domain` (no zone, `placeKind()` says server), `local` (no zone on a person's computer).
- `app/api/node/reach/route.ts` GET `measure()` — by the road: `tunnel` as today; `server` — the name (`hostnameFor`), `dns` = a public A
  record exists (the door's DoH `publicIp`), `answers` = the HTTPS code from the internet (the door's `answers`), `mode: "server"`;
  `server-no-domain` — `mode: "server", domain: false`. The place comes from `lib/hosting/place.mjs` only (741).
- `components/services/service-reach.client.tsx` — the mode `server`: the name as the link, «Узел работает на выделенном сервере: имя
  обслуживает его nginx.», `noDns` / `notAnswering` as today, «Подключить» → the existing POST (`serverReach`, 737-16), then a fresh GET;
  when the node has no Cloudflare token the record to add is shown («A <name> → <ip>», from the POST's `add`). A server without a domain:
  its own sentence, no `localhost`.
- Words: `components/services/service-port.i18n.ts` (en, ru).
- `development-docs/reports/feature-where-the-node-lives-map.md` — row 26: the address card of an element and a service.
- `scripts/reach-road.test.mjs` in the prebuild.

## Done
On aifa.dev every element's and service's card names its real internet name and is green when it answers; on a person's computer
nothing changes.

## Proof
1. aifa.dev after its update, in his Chrome: `/api/node/reach?service=root` → `mode: "server"`, `hostname: "aifa.dev"`, `answers: 200`;
   the card on `/ru/root` green with «aifa.dev» (screenshot); the same for auth and one custom element.
2. `reach-road.test.mjs`: the four fixtures give the four roads; a server record without `via` stays `tunnel` (negative); and on this Mac the
   door still answers `mode: "local"` (home, no domain) — the change did not spread to the home road.
