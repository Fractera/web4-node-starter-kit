# 749-2 — a new element is named at its first click

## Built
- `app/[lang]/(architectLayer)/_components/create-draft-button.client.tsx` — the click opens `AppDialog` «Новый элемент» with one field
  «Название» (`Input`, up to 60 characters, required) and «Создать»; the raw `<button>` becomes `Button` (the file leaves clean). The left
  menu (`_lib/draft-menu.tsx`) passes the dialog's words (`appDialogUi(lang)`, by value from the server).
- `app/api/architect/drafts/route.ts` POST — takes `{ name, native? }`; an empty name → 400 `name-required`; `createDraft` writes the name
  with `writeName(id, name)` (`name-file.cjs`, the one name store of 678-1) — the menu, header, title and dialogs show it at once (678-3).
- `lib/web4-items/birth.ts` `birthArgs` — adds `--name <ownName(id)>` when the core holds a name; `item-birth.mjs` already writes the
  passport `name` from it (as `npm run create --name`).
- `lib/web4-items/drafts.ts` `deleteDraft` — removes the draft's `data/services/<id>/name.json` with it.
- Words of the dialog in the menu's dictionary (en, ru).

## Done
A draft made by the panel's button carries the person's name from the first second; its birth gives the element the same name.

## Proof
1. Chrome on the Mac after the update: «+ Создать элемент» → «Проба имени» → the left menu «ПРОБА ИМЕНИ» and the page title «Проба имени»;
   «Создать» is disabled while the field is empty (negative); then the draft is deleted by its name (749-1) — the menu forgets it.
2. A unit run over a temp folder: `createDraft` with a name writes `name.json`, `displayName` returns it, `deleteDraft` removes it; the
   door's body check refuses `{}` and `{ name: "  " }`; `birthArgs` carries `--name`.

## Not proven live, said aloud
A birth from the panel (minutes and a whole element): its arguments are unit-tested; the first real birth shows the name.
