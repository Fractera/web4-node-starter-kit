# 749-1 — the delete dialog names the element and takes its name

## Built
- `app/[lang]/(architectLayer)/architect/[item]/[[...page]]/page.tsx` — `DeleteElementButton` gets `name={elementLabel(item, lang)}`.
- `app/[lang]/(architectLayer)/_components/delete-element-button.client.tsx` — title «Удалить «{name}» насовсем?»; the line to type is
  the name (select-all, an empty field as since d2b25ccf); the internet address as a muted fact only when the node has a domain (749-D2);
  `match` = the normalised name (749-D1).
- `app/api/architect/items/[id]/route.ts` DELETE — `confirm` checked by `confirmMatches(id, typed)` in `lib/web4-items/element-delete.ts`:
  the element's name for people (`elementDisplayName`), trimmed, spaces folded, case-insensitive; else 409 `confirm-mismatch`, nothing
  removed (as today).
- The draft: `delete-draft-button.client.tsx` and `app/api/architect/drafts/[id]/route.ts` — the same rule (a draft named by 749-2 is
  deleted by its name; an old unnamed one by its address — the fallback of 678-1).
- Words: `_i18n/element-settings.i18n.ts` `removeDialog` (en, ru) and the draft's words in their own dictionary — title with `{name}`,
  label «Название», mismatch «Название не совпадает — ничего не удалено.», the address line.

## Done
The dialog of every custom element and draft names it and asks for its name; no id is printed; a door accepts only the name.

## Proof
1. Chrome on the Mac after the update: «Клип» → «Опасная зона» → «Удалить элемент»: the title says «Клип»; `s8y6x` typed keeps «Удалить
   насовсем» disabled (negative), «Клип» enables it; then «Отмена» — nothing is deleted. Screenshot looked at.
2. `scripts/element-delete-confirm.test.mjs` (esbuild bundle as in `proxy-split.test.mjs`, a temp root with `data/services/<id>/name.json`):
   the name → true; « клип » → true; the id or the address of a named element → false; an unnamed element → its address true.
