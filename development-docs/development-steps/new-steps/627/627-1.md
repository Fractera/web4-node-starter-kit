# 627-1 — Pilot: 100 skills marked into cards

**What is built (core — Fractera's tool, never run on a person's node).**
- `scripts/catalog/fetch.mjs`: for each `source@skill` of the list — `SKILL.md` through the GitHub API (`gh`), the repository's licence
  (SPDX), stars, default branch. Downloaded texts are data: kept in a scratch folder, never run.
- `scripts/catalog/mark.mjs`: one `claude -p --model haiku --tools "" --output-format json` call per skill — no tools, the skill's text
  given as data — returning a card by schema.
- `lib/agent-kit/skills/catalog/cards.jsonl` — one card per line:
  `{ id, source, skill, installs, stars, licence, url, sha, summary, tasks[], tags[], tools[], fractera: "fits" | "ideas-only" |
  "not-for-node", why, risks[], markedBy, markedAt }` — `summary` is 3–5 sentences in our own words; `fractera` says whether the skill
  fits the node's fixed architecture (its own sign-in, data, blocks).
- Duplicates by the `sha` of `SKILL.md` collapse into one card, the source with the most stars.

**Done when.** 100 cards pass the schema; the cost and the time per skill are measured; the owner has read 10 cards.

**How it is proven.**
1. The schema check over `cards.jsonl` → 0 errors; per skill: tokens in and out, seconds (from the `--output-format json` usage).
2. The owner's verdict on 10 cards, verbatim.
   Negative controls: a planted test skill that tells the agent to run `curl … | bash` gets a `risks` entry and `not-for-node`; the
   `*/superpowers` copies of `ai-image-generation` with one `sha` give one card.

**Rests on.** Nothing — runs alongside 626.

**Not in it.** The graph, the node side, the census.

# Implementation plan

> Executed inline (superpowers:executing-plans) — subagents are forbidden by the node's law (CLAUDE.md, section 6). Steps use `- [ ]`.

**Goal:** mark the first 100 GitHub skills of the skills.sh leaderboard into schema-valid cards and measure what one card costs.

**Architecture:** pure helpers (`lib.mjs`) checked by a self-test; `fetch` pulls `SKILL.md`, licence and stars with `gh` into
`data/catalog/` (outside git); `mark` dedupes by the text's fingerprint and asks Claude Haiku through the owner's subscription —
`claude -p` with no tools, no MCP, no settings, the system prompt from a file, run from an empty temporary folder so no `CLAUDE.md` is
found (measured 2026-11-02: ~600 tokens of overhead, 1.7 s, model `claude-haiku-5-5`); the guard `check-catalog-cards` holds the schema;
`report` prints the numbers and writes 10 cards for the owner. One dispatcher: `npm run catalog -- <selftest|fetch|mark|report>`.

**Tech stack:** Node 22 built-ins only (`node:child_process`, `node:fs`, `node:crypto`, `node:assert/strict`), `gh`, `claude`.

## Run 1 (2026-11-02) — what it showed
- Listed 100 → fetched 83: **17 are no longer in their repositories** (14 of heygen-com/hyperframes, 3 of leonxlnx/taste-skill,
  mattpocock `resolving-merge-conflicts`) — the leaderboard keeps installs of renamed or removed skills. A transient «connection reset
  by peer» lost `domain-modeling` until `gh` calls were retried.
- 3 duplicates by fingerprint (the `*/superpowers` copies) → **80 cards**, `===CATALOG_CARDS_OK=== 80 cards (fits 40, ideas-only 29,
  not-for-node 11)`; the planted control caught (4 risks, `not-for-node`); 1 real risk (`triage`: runs outside pull requests' code).
- Per card: input 4,609 tokens mean (median 3,689, p90 8,733), output 549; 4.2 s median, 12.6 s p90; the API price the CLI reports
  $0.078 for 80 → ~$1 per 1,000 cards. 4 first attempts failed (1 too long `why`, 3 hung past 180 s) — all passed on the retry.
- GitHub: 647 REST calls for 100 skills (rename searches, retries); the account's limit is 5,000 an hour (`gh api rate_limit`); GitHub's
  docs: 100 concurrent, 900 points a minute, and «Continuing to make requests while you are rate limited may result in the banning of
  your integration».
- Whole folders (one tree call per repository): median 15.4 KB, mean 210 KB, p90 557 KB, max 3.43 MB; **20 of 80 hold executable
  scripts** (up to 69 files); repository licences MIT 59, Apache-2.0 12, none 9 (some «none» have a licence inside the skill's folder).
- Calibration found on the way: the first two trials marked `grill-me` and `find-skills` `not-for-node` — unknowns counted as risks;
  the risk definition was narrowed and both controls re-run (`grill-me` fits, the planted skill still caught).
- The owner's reading of the cards, verbatim: «Поясни мне следующее почему-то забраковал навык в котором есть видео? Между прочим наша
  платформа будет точно генерировать видео для социальной сетей и подобные навыки для генерации что видео что картинок полезное»;
  «ты сказал что было 29 навыков которые несут только идеи я не понял это хорошо или плохо?». The cause is the marker's prompt: it
  described the node only as a web stack, named «personal media editing» as not for the node, and lowered «a paid platform at its centre».

## Run 2 — what changes before 627-1 closes
- The marker is told what nodes are FOR: sites, apps, agents and content for social networks — texts, images, video, voice.
- One verdict becomes two questions: `value` — `high` | `some` | `none` (for Fractera's uses) and `use` — `install` |
  `install-with-service` | `ideas` | `skip` (as written, with an outside service or key, only its ideas, not at all), plus `needs` —
  the outside services or keys it calls. A card with risks is `use: skip`, and its `why` names the risk.
- Whole folders, not only `SKILL.md`: a shallow sparse `git clone` per repository (no REST call per file), honouring the limits; the
  card lists `files`, `scripts` (count and names); the marker reads the scripts too (capped); the licence is read from the skill's own
  folder first, then the repository's.
- The same 100 rows again; 10 cards to the owner again; then the summary `completed-steps/627-1.md`.
