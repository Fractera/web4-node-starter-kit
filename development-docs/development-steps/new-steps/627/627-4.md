# 627-4 — The readers: `skills_find` and the deep memory

**What is built.**
- Core `skills_find` (`lib/agent-kit/skills/mcp.mjs`): three sources in order — the node's base (full licensed texts), the space
  «skills-catalog» (cards: summary, verdict for Fractera, licence, installs, link, risks), the live CLI only for what the cards do not
  have. A card with `risks` or `use: "skip"` is never proposed; a card with scripts is proposed with their count and installed only
  after a separate yes. The answer follows the instruction's «curiosity first» rule (core `72ae8f0`): each skill with the stars of its
  repository, its installs and the idea it brings. `npm run skills -- market` reads the space first.
- Memory element (`Fractera/fractera-memory-starter`, `lib/memory/solution-search.mjs`): a request no service handles is also looked
  for in the space «skills-catalog», with the threshold of 627-2.

**Done when.** The main agent, asked in Telegram «хочу постить в соцсети и блоги», names catalog skills with their verdict — and, by the
625 rule, asks about a known analog before any plan.

**How it is proven.**
1. Telegram, live: the answer names at least one catalog card with its verdict and link, and the analog question.
2. The MCP harness: the same question returns cards from the space with the live CLI switched off.
   Negative controls: «как починить кран» → nothing; a planted risky card never appears in an answer.

**Rests on.** 627-3.

**Not in it.** The census and the full run (627-5).
