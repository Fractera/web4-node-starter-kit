# 627-2 — The space «skills-catalog» built from the cards and packed

**What is built (core).**
- `scripts/catalog/build.mjs`: from `cards.jsonl` a ready graph the way `to-graph.mjs` builds the base — an entity per skill
  (`catalog:<source>:<skill>`, type `skill`, description = summary + tasks + the verdict for Fractera), entities for tags and tools,
  links skill → tag «serves» and skill → tool «uses», one chunk per card; inserted through `graph-insert` into the space
  `skills-catalog` on Fractera's own node (vectors by `embeddings`).
- The space folder packed (`tar.gz`) with `manifest.json` `{ model, dims, count, sha256, builtAt, cardsSha }`; uploaded as a release
  asset of the core (`skills-catalog-YYYY-MM-DD`); `lib/agent-kit/skills/catalog/release.json` names the asset, its sha256 and the model.
- The threshold for the catalog, measured: 30 questions — 20 with a known right card, 10 outside the catalog.
- Fractera's store of checked copies (decision after run 1): every skill whose licence allows a copy is packed folder by folder with
  its fingerprint and kept in Fractera's own store, named on its card; the store's address is in `release.json`.

**Done when.** The package is on GitHub with its manifest and size, and the catalog's threshold is chosen.

**How it is proven.**
1. On Fractera's node: the query «write a selling headline» puts copywriting cards first.
2. The 30-question table at the chosen threshold. Negative control: the 10 outside questions find nothing above it.
   The package size per 100 cards is written down — it predicts the full run's download.

**Rests on.** 626 (the element `embeddings`), 627-1.

**Not in it.** Any change on a person's node.
