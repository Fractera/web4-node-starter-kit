# 627-6 — Updating the catalog

**What is built (core).** `npm run catalog -- update`: the census again; only skills whose `SKILL.md` changed, or that are new,
are fetched and marked again; then build, pack, a new release, `release.json`. A node takes the new space on its next update (Sync fork
and update) — never by a timer. Whether a skill changed is read from the git blob sha that GitHub gives in the repository tree (kept on
the card next to our fingerprint) — an unchanged skill is not downloaded at all. The owner, 2026-11-02: «Я не понимаю зачем мы должны
скачивать навыки? Разве недостаточно просто сделать разметку графом а вместо того чтобы забивать на нашу собственную память просто
сохранить адрес репозитория?» — a text is downloaded only to be read once for its card, at Fractera, and never ships.

**Done when.** One changed skill is marked again alone and reaches a node after that node's update.

**How it is proven.**
1. The update's log: «marked again 1, kept N».
2. On a node after its update: a query returns the changed card's new text.
   Negative control: an update with no change in the catalog makes no new release.

**Rests on.** 627-5.

**Not in it.** An automatic schedule (only by the owner's word, law 6).
