# 627-6 — Updating the catalog

**What is built (core).** `npm run catalog -- update`: the census again; only skills whose `SKILL.md` `sha` changed, or that are new,
are fetched and marked again; then build, pack, a new release, `release.json`. A node takes the new space on its next update (Sync fork
and update) — never by a timer.

**Done when.** One changed skill is marked again alone and reaches a node after that node's update.

**How it is proven.**
1. The update's log: «marked again 1, kept N».
2. On a node after its update: a query returns the changed card's new text.
   Negative control: an update with no change in the catalog makes no new release.

**Rests on.** 627-5.

**Not in it.** An automatic schedule (only by the owner's word, law 6).
