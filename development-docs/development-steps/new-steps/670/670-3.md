# 670-3 — The core's map: every element's area and what it may grow into

## Why
The owner: «Какие тогда ещё в будущем это элемент может решать задачи? А куда это описать?» Today an element is described only by what
it does NOW (passport, card skills, doors) and by its role (one sentence in `roles.json`). Nothing says which jobs it is the natural home
for tomorrow — so a new kind of job either lands nowhere (a new element each time — a zoo of one-off servers) or on a false match
(storage 0.38 for a YouTube summary). The main agent holds the map of the hands (the soul); the area is part of that map.

## What is built
- `WEB4-ITEMS-REGISTRY/areas.json` — the default for every node: for each shipped element `{ "area": "<one sentence>", "growsInto":
  ["<plain words of a job>", …] }`; `data/node/areas.json` — the node's own (outside git), wins, as `data/node/roles.json` does.
- `scripts/main-agent-cli.mjs`: `areas()` beside `roles()`; `npm run role -- <id> "<role>" [--area "<one sentence>"] [--grows "<job>;
  <job>"]` (an area alone changes only the area); `npm run create … [--area …] [--grows …]` writes it at birth.
- `lib/a2a/self-description.cjs`: `describeAll` takes `areas`; `cardText` prints «Its area: … · may grow into: …».
- `roles.json` stays strings — its readers (`lib/web4-items/dashboard-rows.ts`, every element's `npm run passport -- project`) are not
  touched.

## What counts as done
`npm run card -- <id>` prints the area and «may grow into» for every shipped element; a value set with `role --area` wins over the
default.

## How it is proven
1. **The command.** `npm run card -- memory` shows its default area; `npm run role -- root "<its role>" --area "<test sentence>"` →
   `card root` shows it; the old value comes back after the check.
2. **The door of the roles' readers.** `GET /api/node/projects` returns the same string roles as before the change.
   **Negative control:** `role --grows` with an empty list or an area over 300 characters → refused, the file unchanged.

## Rests on
548-10 (`roles.json`), 603-1 (self-description).

## Not in it
The element's own claim of growth in its passport (templates, 671); search (670-4).
