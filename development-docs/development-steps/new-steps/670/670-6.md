# 670-6 — The Lagrix rung as a contract, and the a2a inbound order on paper

## Why
The owner: «lagrix прямо сейчас ещё не создан поэтому он всегда по дефолту возвращает ничего не найдено. Но этот шаг лучше сразу
закрепить чтобы в будущем … подключили без сильных конфликтов»; «a2a it must discribed for feature».

## What is built
- **The contract.** `lib/web4-items/lagrix-simulated.mjs` (548-9: f2f only, built by Lagrix documents 17 and 20, `mode: "simulation"`,
  empty `results`, a journal line) → one entry `lagrixSearch(words, { kinds })` with two kinds: `a2a` — an agent that sells the result of
  its work (document 17: discovery by a capability tag, the request carries only the country and the adult flag, $0.01 USDC per result
  list), `f2f` — a whole element (document 20, its technical card); both in the same shape, both simulated, nothing paid.
- `npm run lagrix -- <words>` prints both kinds, «simulated — the network is not live», and the next rung.
- **A shape test** (`npm run test:lagrix-contract`): validates the answer — network, protocol, mode, request, fee, results, found. Today
  the simulation passes it; the real adapter will pass the same test unchanged.
- **The rule «only where it pays»**, into the words of 670-5: the rung is called after the node found nobody and before a buy-or-build
  decision — never on a plain question (a live search will cost money).
- **The a2a plan**: `new-steps/<next free>-a2a-inbound-order-wakes-the-element-worker.md` — the path: an outside agent → the element's
  `a2aEndpoint` (`SendMessage`) through the node's own domain → `proxy.ts` opens only that path, only for `visibility: network` and Web4
  on → the gatekeeper if it sleeps → an A2A Task answered at once (the cold start hidden behind the task's states) → the endpoint wakes
  its OWN worker (code → its own agent) or runs a door with no model → the artifact → Lagrix escrow (document 04) → `order:save` without
  personal data → reputation from paid work only. What exists, what is missing, the open questions — first of all who pays for the
  model of an outside order (skill `provider-rules`, read from the primary source when the plan is written). Linked from
  `lib/a2a/STANDARD.md` and `use-i2i-a2a-f2f`. Every claim about Lagrix links its document (github.com/lagrix-dev/lagrix).

## What counts as done
`npm run lagrix` answers both kinds, marked simulation, and the shape test passes; the a2a plan waits in `new-steps/` and is linked.

## How it is proven
1. **The test.** Green on the simulation. **Negative control:** an answer without `mode` or without `results` fails it.
2. **The command on the owner's node** (after 670-7's update): «youtube video summary» → a2a and f2f «not found (simulated)», the
   journal line written.
