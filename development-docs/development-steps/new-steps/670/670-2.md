# 670-2 — A neighbour's job wakes the element's worker, naming which of its agents

## Why
Measured 2026-11-07: `npm run task` always sends `modes.withWord(text, 'build')` — every job the main agent hands an element starts its
BUILDER: the heavy session with every build skill, the laws of building, the temptation to change code for a job that changes only data.
The bridge already runs a working session `<id>--work` for a text that opens with «Working process:» (552-4, `lib/agent-kit/modes.cjs`
`sessionKey`), but nothing in the core can send one.

## What is built
- `scripts/main-agent-cli.mjs` `task`: `--work` — the text goes with the word «Working process:», so an element with skill groups starts
  (or receives in its live) `<id>--work`; an element without groups has one session — the command says so in its line. `--skill <id>` —
  checked against the element's own skills from its card (`describeAll`); unknown → refusal listing them; the text begins
  «Working process: skill <id> — …». `--dry` — prints the wake body and wakes nothing (as `review --dry`).
- `===TASK_OK===` names the session (`<id>--work` or `<id>`); `markWoken` keeps the session key so `close` closes the right one.
- Skills: `route-to-element`, `handle-need`, `ask-element` — a job for an element → `--work [--skill]`, building → as before. The
  worker's answer comes back as it does today: `npm run reply-core` → `npm run state`.

## What counts as done
`task --work --skill <x>` reaches `<id>--work` with the skill named; `task` without `--work` behaves exactly as before.

## How it is proven
1. **The command.** `--dry` prints the word «Working process:» and the skill; an unknown skill id → refused with the card's list;
   **negative control:** `task --dry` without `--work` prints «Build process:» — nothing changed for the old path.
2. **The live session, after the owner's yes with its price** (one short job, a few requests): the core's sessions door
   (`/api/agents/sessions`) lists `<id>--work`; the build session of that element is not started.

## Rests on
552-4 (modes), the wake door `app/api/agents/wake/route.ts` (unchanged: a Telegram question for an element with a bot, 300 MB per
session).

## Not in it
Queueing a job when memory is short; a Telegram bot per agent; the element side (its skills answering a `skill <id>` job — 671).
