# 642-3 — The node update: one terminal through all its stages

**What is built.** «Обновить узел из форка» opens the same terminal under the core card: the update's own log
(`GET /api/node/update` → `log`, `stage`) while the core is up (fork, elements), the build reader during the core's build, the update's
result after (skills). The stage is named above the lines («форк», «элементы», «сборка ядра», «навыки»).

**Done when.** The owner's next «Обновить узел из форка» is watched from the start to «Узел обновлён» on one screen.

**How it is proven.** 1. Board on stubs through the four stages, the source switching to the reader and back. Negative control: a
finished update opens no terminal on load. 2. Live: the owner's next update; the stages and the result in the terminal, the reader's
`/status` sampled during the core stage.

**Rests on.** 642-2. **Not in it.** Changes to what the update does.
