# 642-2 — The core: a build reader while the lid is closed

**What is built.** `scripts/build-reader.mjs`: a plain Node HTTP server on `127.0.0.1:<core port + 1000>` (a free port named in the
registry's spirit, measured before use), started detached by `serve.mjs rebuild` right after `closeLid` and stopped right before
`openLid` (its pid in `data/node/build-reader.json`; an orphan is stopped by the next `serve:start`). It answers `GET /status` with the
stage and the last 200 lines of the build's output (`logs/core-deploy.log` or the update's log), with CORS for the core's localhost
origin only. `core-deploy.client.tsx` + board: after the start, the terminal opens under the core card; while the core answers — its
own door; when the core is silent — the reader; when the core answers again — the result, the page refreshes its state itself.

**Done when.** On the owner's node «Развернуть ядро» shows moving lines for the whole 8–12 minutes and the result after.

**How it is proven.** 1. A probe of the reader alone (start, `/status` answers with the file's tail, refuses a non-local Origin, stops
on its pid file) and of the board on stubs (core silent → reader's lines; core back → result). Negative control: the reader is not
running → the board says «ядро собирается, журнал недоступен», never an empty terminal. 2. Live: one core rebuild on the owner's
node; the reader's `/status` sampled during the build (lines grow, stage changes), the core's port never taken by it, the internet
address answering with the copy as before.

**Rests on.** 642-1, 553, 555. **Not in it.** The terminal through the internet during the build.
