# 726-4 — balances and the day's burn

**What is built.** First a measurement, written into this file: what each provider the node uses exposes about state and balance, read
at its primary source (OpenAI: the usage and costs endpoints and the key they require; exa.ai; others the subscriptions name) — no claim
from memory. Then per provider: the state (active, the last error), the balance where the API gives it, and the burn from the ledger
(today, per hour, the projection to the end of the day) against a daily budget the person sets on the «Все подписки» page. A poll only on
a request or at a session start (a few HTTP calls, no model, the price named).

**Done when.** For each service the page answers «active?» and «will it last today?», or says plainly that the provider does not tell.

**Proven by.** Plane 1 — the projection over a fixture of journal lines (a budget crossed at 15:00 → «до вечера не хватит»); negative: no
lines → «нет расхода», never a guess. Plane 2 — on the owner's node one real poll where a provider allows it, the numbers compared with
the provider's own dashboard by the owner.

**Rests on.** 726-1…3. **Not in it.** Paying or topping up — the person's action in the provider's own screen.
