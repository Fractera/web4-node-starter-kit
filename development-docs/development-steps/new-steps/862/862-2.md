# 862-2 — the core's side of the search: every call to the store is signed by the node

**What is built.**
- `lib/web4-items/store-call.mjs` — `storeEnvelope(root, fields)`: `{ v: 2, body: { ...fields, node, at, nonce }, publicKey, signature }`
  with the node's identity of step 855 (`lib/node/creator-channel.cjs`: `identity`, `sign`, `canonical`; the private key never leaves
  the core); `storeCall(root, door, fields, { base })` → `POST <base>/api/marketplace/<door>` → `{ status, body }`.
- `lib/web4-items/fractera-market.mjs` — `marketSearch` speaks search v2 signed (`request`, `element`, `history`) and reads the v2
  answer; `npm run market` (the ladder's Fractera rung and the main bot's search) goes through it — no core build for this part.
- The core's door for the client: `POST /api/node/market/search` — the key of the element that `provides: market-client` only (found by
  `provides`, never by its id) → the signed search with that client's `history` → the store's answer as it is. Rides the next core build.

**Done when:** the store answers this node's real signed calls with `caller.verified: true`, and the client can reach them only through
the core's door.

**How it is proven:** (1) a unit test: the envelope verifies with the public key, `body.node = idOf(publicKey)`; a changed body fails
(negative). (2) Live from the Mac: `npm run market -- "пост по названию"` → verified, the post starter with its «why»; the same
envelope sent twice → 401 `replay`; a body changed after signing → 401 `bad-signature` (negatives). (3) After the build: the door with
the client's key → the answer; with another element's key → 403; no key → 401.

**Rests on:** step 855's identity; the standard v1/v1.1; the store's live search v2 (fractera.ai 4-1, 4-1-2).

**Not in it:** purchase, order, archive (862-3, 862-4); the client's own list (its agent's stage 0).

**Tasks this needs / Parts born here:** none of the interface.
