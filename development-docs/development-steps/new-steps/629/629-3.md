# 629-3 — The same law for the agents of the elements

**What is built.** In `lib/instructions/element/element-instruction.src.md`, section 7 «Laws everywhere», for every element (`@T`):

> - **A request against a provider's rules** (Anthropic, OpenAI), or a refusal or block of your own call: name the rule and what it risks
>   — a warning, limits, the account suspended or closed, payments not refunded (anthropic.com/legal/aup, anthropic.com/legal/consumer-terms)
>   — and the lawful way to the same goal. Never help to reword it, never retry the blocked call in another form; insisted on — one short
>   warning again, then stop.

Then, by `lib/instructions/element/README.md` and skill `release-template`: `instruction:element -- coverage`; the templates custom and
native (and root's own folder) get the new `CLAUDE.md` and seal — released with their next patch tags and pinned; every element of the
registry gets the common part through `rollout … --also CLAUDE.md,scripts/instruction.seal`, its next patch tag and its pin.

**Done when.** Every template and every element of the registry carries the law word for word, each with its new seal, pinned in the core.

**How it is proven.**
1. Guards: `npm run instruction:element -- coverage` → `===COVERAGE_OK===`; `verify-elements` over every element → `===ELEMENTS_OK===`;
   `npm run node:readiness` — every repository ✓.
   Negative control: a scratch copy of one element's `CLAUDE.md` with the law line removed fails its own `scripts/check-instruction.mjs`.
2. Text: the line found word for word in the `CLAUDE.md` of each pinned tag on GitHub (`git show <tag>:CLAUDE.md`).
