## The owner's choice (2026-11-06, the window, verbatim)

## What is built

1. **The core — the catalog for CONFIG lists every element of the registry** (`catalogEntries`): a silent element stays under its name
   from the core's section (632-1's naming) with its address; an off one is marked `off` (what the element header does with it — the
   owner's choice below). The push after `node:update` happens once, after the last element is up (the installer already waits for
   health), not in the middle.
2. **The core — after that push it calls each element's own door `POST /api/settings/changed`** (the key it already holds,
   `SETTINGS_SECRET`): the element pulls the copy at once and subscribes again — an action following the person's `node:update`, no
   timer. The core's element deletion (`delete`) also removes the subscriber from CONFIG (`djlgb`).
3. **Every element (the custom template, the native template, root, the twelve natives)** — `projectCatalog` / `catalogGroup`: a card
   with no public `href` uses `local` (the owner at this computer); the tab is drawn whenever the copy has a catalog. The rule «it goes
   away only with the link to CONFIG off» (553) stays: an element living on its own files draws its own header.
4. **CONFIG** — `subscribe` drops an entry whose port answers as another element (the trial port), and `subscribers.json` is written only
   to the data folder (the stale copy inside `.next-a` gone).
