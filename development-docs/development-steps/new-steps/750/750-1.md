# 750-1 — deleting an element closes its agent first

- **Built:** `lib/web4-items/element-delete.ts` — a stage 0 before pm2: close the element's sessions `<id>` and `<id>--work` through the same
  agent-kit call the door `/api/agents/done {close}` uses, while the registry still names the element; then `supervision.cjs` drops its
  record (a new `forget(id)`); both appear in the steps list.
- **Done:** after a deletion no `claude` runs in the element's folder and `supervision.json` does not name it.
- **Proof:** a node test of the stage order with a stubbed kit (close before `registry`; a session already off → `no-session`, not a
  failure) · live on the Mac: a throwaway element born (`create --name`), its agent woken, deleted — `ps` shows no `claude` with its
  folder, `supervise` lists nothing for it.
- **Not in it:** agents of other elements; Telegram bots of the element (they stop with its process).
- **Tasks / parts:** no interface. Parts born here: none.
