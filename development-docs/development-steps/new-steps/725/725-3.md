# 725-3 — the gate: no new interface file before the parts were asked; `replaces` enforced

**What is built.** A PreToolUse hook in the core's settings (beside `system-part.mjs guard`): a Write that CREATES a file under the
interface folders (`components/**`, `app/[lang]/(architectLayer)/**/_components/**`, `sections/**`, `_tools/**/client/**`) is refused
(exit 2) until this session asked `parts_find` (its marker); the reason names `parts_find` and the words to try. Edits of existing files
pass. Measured first: the hook input carries the session id (Claude Code hook fields) — if not, the marker keys on the transcript path.
`check:parts-use` in prebuild: every card's `replaces` — e.g. `VoiceTextarea` replaces direct imports of
`_tools/voice-input/client/voice-input.client` outside `components/form/` and the tools — red with the part to use.

**Done when.** A session cannot create an interface file blind, and a superseded import cannot reach a build.

**Proven by.** Plane 1 — hook samples: a new `components/x/a.client.tsx` without a marker → exit 2 with the reason; with a marker →
exit 0; an edit of an existing file → exit 0 (negative control); `check:parts-use` red on the 722-4 window's import (kept in a scratch
copy), green on the core after 722-8. Plane 2 — a live session on the owner's node: the refusal arrives as the agent's tool result.

**Rests on.** 725-2, the hook pattern of 720. **Not in it.** Element sessions (725-5).
