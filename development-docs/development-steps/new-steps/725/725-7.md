The owner, 2026-11-11, verbatim: «мало иметь технологию для поиска инструмента гораздо важнее иметь технологию для того чтобы из того
процесса в котором ты находишься в процессе строительства понять что именно сейчас ты создаёшь инструмент этот инструмент который будет

Measured the same day: the row «state dot + element name» was written by hand three times in one step (`menu-more`, `menu-search`,
`menu-ai`) and extracted only at the third, after the owner's verdict (722-8). Search alone would not have caught it — there was nothing to
find yet; the part was being born.

**What is built.** Three signals that fire inside the build, not after it:
1. **The declaration at birth.** The gate of 725-3 lets a NEW interface file be written only when its first lines say what it is: a part
   (`// @part <id> — <what it does>`; the card `part.json` follows in the same commit, `check:parts-map` holds it) or local
   (`// @local — <why no one else needs it>`). The agent decides at the moment of creation, with the question in front of it; the refusal
   text asks it in the owner's words.
2. **The second copy.** `check:parts-dup` in prebuild, model-free: the same JSX skeleton or the same long class string (the interface-design
   tell: «the same long className sprayed everywhere — that is a missing component») in two files outside one part → red at the SECOND copy,
   naming both files and the part to extract. The 722 rows would have stopped at `menu-search`.
3. **The plan and the summary ask it.** The substep template (`use-development-steps`, 724-3) carries «Parts born here: …» in the plan and
   in the summary; a born part is loaded into the graph — the «база связей» — by `npm run parts-base` at the build, so the next session
   finds it with `parts_find`.

**Done when.** A reusable piece cannot be born unnamed: either it is declared a part at its first line, or the second copy stops the build.

**Proven by.** Plane 1 — samples: a new file without a declaration → refused with the question; with `@part` and no card → `check:parts-map`
red; with `@local` → passes; the three old row copies restored in a scratch tree → `check:parts-dup` red at the second, naming both
(negative control: two unrelated components with short shared classes → green). Plane 2 — on the owner's node the next interface substep
(726-3) shows its «Parts born here» line and `parts_find` finds the part in the following session.

**Rests on.** 725-1 (the map), 725-2 (the graph and the tool), 725-3 (the gate). **Not in it.** Moving old duplicates (725-6 lists them).
