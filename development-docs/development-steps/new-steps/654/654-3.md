# 654-3 — vectors: the element's own collections (vectors element)

**Repository:** `Fractera/fractera-vectors-starter` `main` → next patch after v1.2.6; the core pins it.

## What is built

- `lib/data-store/vectors.mjs`, with an element key (`req.element`, 654-1): the element's collection `faq` is kept as `el/<id>/faq` and
  its record id `x` as `el/<id>/x` — the vec0 partition stays the collection, so a search still touches only one collection; every
  answer gives the element its own names back (`faq`, `x`), never the prefix.
- `POST /vectors` — writes only under its own prefix (the same id replaces only its own record; an id of the node or of another element
  can never be hit); `POST /vectors/search` with `collection` — its own collection only; **without `collection` — only its own
  collections**, searched one by one and merged by score (today it searches every collection of the node, NOW-21); `DELETE /vectors/:id` —
  only its own (another's → 404); `GET /vectors/status` — the store's model and index, and `count` of its own records.
- The master key: as today (the memory's `memory-said--root`, the core's `memory-<agent>` and `self-*` stay where they are); an element's
  collection is named in full (`el/root/faq`); a name of the node beginning with `el/` is refused — that prefix is the elements'.
- README of vectors: section «Whose vectors» (the prefix, the refusals, the main agent's view).

## Done when

A text stored with A's key is found by A and by the master key, and never by B — with or without a collection.

## How it is proven (named in advance)

1. **Doors on the owner's node** (proof script, keys never printed): A = `root` stores «у Бориса жёлтый велосипед, проверка 654» in
   `faq`; A's search «Какой велосипед у Бориса?» in `faq` and without a collection → found, collection `faq`; **B = `blocks`, the same
   search with `collection: faq` and without one → not found (negative control)**; B's `DELETE` of A's id → 404 and A still finds it; the
   master key in `el/root/faq` → found; the main agent's own diary search (`npm run memory -- …` / `embed.cjs` on `memory-<agent>`) answers
   as before.
2. **The rows directly:** with the master key, the record lies in the collection `el/root/faq` and its id begins `el/root/`; `vectors/status`
   with A counts 1, with the master key the node's whole count. Lab: unit checks of the prefix (strip, refuse `el/` from the node, a
   crafted `../` or a second slash cannot reach another prefix), the three index modes (`partitioned`, `flat`, `scan`) on a scratch store,
   prebuild 0, `tsc` 0, `next build` 0; CI three-os green. The proof deletes its record.
