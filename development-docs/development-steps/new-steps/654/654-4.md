# 654-4 — graph: the element's own space; the node by `DATA_SECRET` (graph element, memory element, core)

**Repositories:** `Fractera/fractera-graph-lightrag-starter` `main` → next patch after v1.2.6; `fractera-memory-starter` → next patch;
`Fractera/web4-node-starter-kit` (the core's graph calls, the pins). Delivered together with 654-5 in ONE `node:update` (654-main §3).

## What is built

- **Graph doors** `app/api/graph-insert|query|status/route.ts`: the caller is checked by the graph's own copy of the key
  (`lib/element-key.mjs`, the same test vector as `auth.mjs` of 654-1): `X-Data-Secret` = the node (every space and the shared graph, as
  today); `X-Element-Key` = that element. **`X-Node-Key` (`SETTINGS_SECRET`) no longer opens the graph** — custom elements hold it until
  step 655, so a graph that took it would stay open to every element (654-main D2). 401 names the two headers that work.
- An element's space: without `space` — `el-<id>`; with `space: "<name>"` — `el-<id>--<name>`; it never reaches the shared graph, a space
  of the node (`memory`, `memory-root`, …) or another element's. The name rule of spaces is widened to fit `el-` + a 63-character id +
  `--` + a name (`lib/graph/run.mjs`, README). `graph-status` with an element key counts its own spaces.
- **The core's graph calls** → `X-Data-Secret`: `lib/agent-kit/skills/find.mjs` (`graphCall`, used by `skills_find` and `scripts/skills.mjs`
  base-check and the skills base load). **The memory's graph calls** → `X-Data-Secret`: `lib/memory/node.mjs` (the graph; its embeddings
  call stays `X-Node-Key` — the embeddings element is not a store and keeps no one's data), `lib/memory/solution-search.mjs`,
  `lib/memory/fractera/knowledge.ts`.
- The graph's A2A card names the new headers (guard `check:a2a-card`); the core's `lib/a2a/passport.mjs` `KEYS` gets `X-Element-Key`.
- README of graph: «Spaces» gets «An element's own space» and the change of the node's header.

## Done when

An entity stored with A's key is found by A and never by B, the node's skills search and the memory still find through the graph, and the
shared node key opens the graph no more.

## How it is proven (named in advance)

1. **Doors on the owner's node** (proof script, keys never printed): B = `blocks` inserts «Зонт-654» with no space → 200 (`el-blocks`);
   A = `root` with `space: "proof-654"` inserts «Велосипед-654» → 200 (`el-root--proof-654`); each finds its own; **B's query for
   «Велосипед-654», with `space: "proof-654"` and without → `found: false` (negative control — the same sub-space name is B's own, not A's)**;
   A with `space: "memory-root"` and «Аня» → `found: false` (its own `el-root--memory-root`, never the memory's); `X-Node-Key` → 401;
   `npm run skills -- find "опубликовать пост в инстаграм"` (the core) → skills found as before; `npm run remind -- "Что лежит у Ани в
   шкафу?"` → «зонт».
2. **The files directly:** `<SERVICE_DATA_DIR>/spaces/el-blocks/` and `spaces/el-root--proof-654/` exist; `graph-status` with the master key
   counts the shared graph as before the proof (1092 entities on 2026-11-05 — unchanged by the proof). The proof deletes its two space
   folders (the graph cannot delete an entity yet). Lab: unit checks of the name mapping (a crafted `space` with `--`, `/`, `..`, upper case
   or 200 characters cannot leave the element's prefix), prebuild 0, `tsc` 0, `next build` 0; CI three-os green on graph, memory and core.
