# 654-2 — storage: whose file, public or private (storage element, memory element)

**Repositories:** `Fractera/fractera-storage-starter` `main` → next patch (v1.1.23 is released, not pinned — this release supersedes it);
`Fractera/fractera-memory-starter` `main` → next patch after v2.2.22; the core pins both. One delivery.

## What is built

- **Storage** `lib/data-store/media.mjs`: two late columns on `media` — `owner TEXT NOT NULL DEFAULT 'node'` and `visibility TEXT NOT NULL
  DEFAULT 'public'` (every record of today stays the node's and public — 654-main D5); `icon_sets` the same `owner`.
- With an element key (`req.element`, 654-1): `POST /media/upload` writes `owner = <id>` and takes `visibility` (`public` | `private`,
  default `public`); `GET /media` lists the element's own records and the node's public ones — never another element's; `PATCH`,
  `DELETE`, `/trim`, `/generate-icons` act only on its own records (another's → 404, the same answer as a missing one); `/thumb` and
  `/file` read its own records and the node's public ones.
- **A private file leaves only when asked by name** (654-main D4): `GET /media/:id/file` and `/thumb` serve a `private` record only with
  `?private=1` and the owner's key or the master key; without it — 404. So the public route `/api/media/<id>/file` of every installed
  element and of the core (the same code everywhere, master key, no flag) stops serving private files the moment storage is updated.
- The master key: everything as today, plus `?owner=<id>` on `GET /media` (the main agent sees an element's files) and the new fields in
  `PATCH` (`visibility`, `owner`).
- **Memory** (`lib/memory/fractera/objects.ts`, `media-ingest.mjs`): every object it uploads goes `visibility: private`; its own reads of
  a file (`fileOf`, `open_object`'s file) ask `?private=1`; once per start it marks its existing objects private (the ids it already
  knows from its rows and the `memory-objects*` collections; idempotent, logged with a count).
- README of storage: section «Whose file» (owner, visibility, the refusals, the public route, `?private=1`).

## Done when

The memory's file is no longer served through any public route, a page image still is, and an element's private file is seen only by
that element and the node.

   Ани?"` names the file; `/v1/objects/<id>/file?source=build` → 200).
2. **Keys and rows** (proof script, keys never printed): A = `root` uploads `p654.txt` private and `i654.png` public; B = `blocks`:
   `GET /media` lists neither (negative), `/file` of both → 404, `DELETE` of A's → 404 and the record stays; A lists both and reads
   `p654.txt` with `?private=1`; the master key `?owner=root` lists both; the rows carry `owner = root` and the memory's objects
   `visibility = private`. The proof deletes its two files. Lab: the ladder on a copy of a `media.db` with old rows (they read `node` /
   `public`), prebuild 0, `tsc` 0, `next build` 0; CI three-os green on both repositories.
