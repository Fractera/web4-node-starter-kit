# 640-2 — Priority: the person's own skills are searched first

**What is built (core).** `findInCatalogFile` (`lib/agent-kit/skills/catalog-index.mjs`) searches the own index first: an own skill that
fits the request (its threshold measured on a small fixture, not guessed) stands FIRST, named «your skill — you suggested it on <date>»,
then the catalog's cards, the same skill never twice. The readers follow without change of their own: `skills_find` (MCP), the core's
door `POST /api/skills/catalog` (so the elements and memory's `findSolution` see it too), `npm run skills -- market`.

**Done when.** A fitting request shows the own skill above the catalog; an unrelated one does not show it.

**How it is proven.**
1. Machine: a temporary node with one kept skill (`coreyhaines31/marketingskills@social` kept as own) — «хочу постить в соцсети и блоги»
   → it first, marked own, not repeated among the catalog cards; a fixture of 10 fitting and 10 unrelated requests for the own threshold.
   Negative control: «как починить кран» → no own skill, no catalog card.
2. The door plane: `POST /api/skills/catalog` on the temporary root returns the own skill first (the narrow `tsc` over the door 0 errors).
