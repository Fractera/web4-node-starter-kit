# 640-1 — Keep: a skill the person liked goes into the node's own store

**What is built (core).** `npm run skills -- keep <owner/repo@skill> [--said "<words>"]` — after 628's `adopt` judged it and the person
said yes: the checked folder (its fingerprint equal to the judged one; «skip» refused; scripts only with `--scripts-yes`) is copied to
`data/node/skills/own/<owner__repo>/<skill>/` with `SOURCE.md` («Origin: suggested by the person», their words, the date) and its card;
its pieces (`cardPieces`: the summary and each task) get vectors from the node's `embeddings` and join the own index
(`data/node/skills/own/index/` — `vectors.f32`, `rows.json`, `manifest.json`, the same model and dimensions as the catalog).
`npm run skills -- own` lists the kept skills; `skills -- forget <id>` removes one and rebuilds the index. Module
`lib/agent-kit/skills/own.mjs`; the skill `adopt-suggested-skill` gets the «keep for later» road.

**Done when.** A judged skill is kept, listed and indexed; nothing reaches an element.

**How it is proven.**
1. Machine: on a temporary node root with the real `embeddings` — keep one judged skill → the folder's fingerprint equals the card, the
   index has its rows, `own` lists it. Negative controls: a «skip» card refused; a file changed after the judging refused; another
   model's index refused by name.
2. Text: `SOURCE.md` of the kept copy names the origin, the person's words and the fingerprint; `forget` leaves no row behind.

**Not in it.** Search priority (640-2), installing into an element (640-3).
