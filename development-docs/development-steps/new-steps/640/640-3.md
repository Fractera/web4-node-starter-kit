# 640-3 — Install: any found skill into an element, by its fingerprint

**What is built (core).** `npm run skills -- hand <owner/repo@skill> --to <element> [--send] [--scripts-yes]` — one road for every skill
`skills_find` can propose:
- an own skill → its kept copy;
- a catalog skill → Fractera's store at the commit pinned in `release.json` (each file by raw link, its git blob checked against the
  store's `manifest.json`, the folder's fingerprint against the card); the store does not answer → the original on GitHub, taken only
  with the same fingerprint; a skill whose licence allows no copy → refused with its link («a card and a link»);
- packed with `SOURCE.md` (origin: own / Fractera's catalog, the source, the licence, the fingerprint) into the archive the door
  `GET /api/skills/suggested` serves (628's door, its id widened to `own` and `catalog` copies), and the element's own agent gets 628's
  task text (download with the node key, sha256, unpack into `.claude/skills/`, commit, report).
628's `adopt-hand` becomes this command's suggested-skill case.

**Done when.** An own skill and a catalog skill are both packed from a checked copy and their tasks name the right sha256.

**How it is proven.**
1. Machine: a catalog skill fetched from the real store — every blob and the fingerprint match; the same with the store's URL broken →
   taken from GitHub, same fingerprint. Negative controls: one byte changed in a downloaded file → refused; a skill with scripts without
   `--scripts-yes` → refused; a «licence allows no copy» card → refused with its link.
2. The door: `GET /api/skills/suggested?id=…` on the temporary root returns the archive whose sha256 equals the task's; a path walk id →
   400.
