# 640-4 — The live check: kept, found first, installed, working — then the verdict

**What is run.** On the owner's node after «Sync fork» + `npm run node:update`, the main agent in Telegram on Opus (a Haiku session is
not a test of the architecture), at most three phrases from the owner:
1. «смотри, интересный навык <link>, может пригодится» → judged, the person's yes → kept (`skills -- own` lists it);
2. a request it fits → `skills_find` shows it first, «ваш навык»;
3. «поставь его в <element> и сделай <a small task with it>» → `skills -- hand … --send` → the element's agent downloads, checks the
   sha256, commits into `.claude/skills/`, then does the task — its transcript shows the skill loaded.
The same road once more for one catalog skill (from Fractera's store) by the main agent's own command, on the owner's word.

**Done when.** Both skills — one own, one from the catalog — are in an element's git history and one of them was used in a real task.

**How it is proven.**
1. Transcripts: the main agent's session (skills_find → own first; hand), the element agent's session (download, sha256, commit, the
   Skill load in the task).
2. Git: the element's commit «Skill <name> from <source> …» with the fingerprint; the file tree equals the checked copy. Negative
   control: the element's `.claude/skills/` had no such skill before (its previous commit).

**Then.** The written verdict to the owner on «ready for one person»: what is proven, what is not, what waits for him (638-2, 629-3).

**Rests on.** 640-2, 640-3.

**Not in it.** Changes to the sealed instruction; more phrases than three.
