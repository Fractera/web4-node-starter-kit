# 626-2 — The native element `embeddings` is born

**What is built.**
- Born with `node scripts/item-birth.mjs --native` (address `embeddings`); its own repository `Fractera/fractera-embeddings-starter`.
- The runtime chosen in 626-1. The model file is downloaded at install from the element's own GitHub release with a sha256 check and kept
  in the element's data folder (outside git). The model loads at the element's start and stays.
- Doors, loopback, node key `X-Node-Key`:
  - `POST /api/embed` `{ texts: string[] }` (up to 256 texts) → `{ model, dims, vectors }`;
  - `GET /api/embed-status` → `{ model, dims, ready, loadedMs, rssMb, calls }` (`calls` counts texts embedded since start — 627-3 uses it).
- Passport: native, on by default, the memory price from 626-1. README: how to call it, the price, «changing the model means recounting
  every stored vector — the owner decides». The A2A card names both doors (`check:a2a-card`).
- Core: the registry entry — id `embeddings`, kind core, required, the pinned tag, a port from the block (`lib/server-port.cjs`).

**Done when.** A fresh `npm run services:install` on the Mac brings the element up with its model, and both doors answer.

**How it is proven.**
1. Door: `POST /api/embed` with «Привет» and «Hello» → two 384-number vectors; cosine with the 626-1 vectors of the same texts ≥ 0.999.
2. Process: `npm run serve:status` shows the element online; after a restart `embed-status` is `ready: true` again.
   Negative controls: without the node key → 401; a model file with a wrong sha256 at install → a named refusal, the element does not
   start on a broken model.

**Rests on.** 626-1.

**Not in it.** Any consumer switched to it.
