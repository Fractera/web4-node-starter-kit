# 626-3 — The vectors element counts through `embeddings`

**What is built.**
- In `Fractera/fractera-vectors-starter`: a text that arrives without a ready vector (`POST /vectors`, `POST /vectors/search` with
  `query`) is counted by `embeddings` `POST /api/embed` instead of OpenAI (`lib/data-store/vectors.mjs`); the model and the size come
  from `embeddings` `GET /api/embed-status`; `OPENAI_API_KEY` is no longer read. At start, a store whose recorded model differs is set
  aside — `data/vectors.db` → `data/vectors.openai-<date>.db` — and a new 384 index is made (clean slate, owner 2026-11-02).
- Core `scripts/services-install.mjs`: `EMBED_MODEL` / `EMBED_DIMS` no longer `text-embedding-3-large` / `3072`; the vectors element
  learns both from `embeddings`.
- The element's README: «Environment», «Changing the model».

**Done when.** `/vectors/status` answers `{ configured: true, model: "…MiniLM-L12…", dims: 384 }`, and a text stored without a vector is
found by a query text.

**How it is proven.**
1. Door: store «the taxi from the airport cost 40 euro», search «how much was the taxi» → it comes first. Negative control: the search
   «kitchen faucet» scores clearly below it.
2. Files: `data/vectors.openai-<date>.db` exists with its old size untouched; the new `data/vectors.db` holds 384-number vectors.

**Rests on.** 626-2.

**Not in it.** The callers that today send ready vectors (626-4, 626-6).
