# 626-5 — The graph counts through `embeddings` and works with no OpenAI key

**What is built (in `Fractera/fractera-graph-lightrag-starter`).**
- LightRAG's `embedding_func` in `services/graph/graph.py` calls `embeddings` `POST /api/embed` (384 numbers) instead of OpenAI
  `text-embedding-3-small` (1536).
- `keyFound` no longer gates the graph; `graph-status` names `embedModel` and its size from `embeddings`.
- At the first run with a different model, the old `<SERVICE_DATA_DIR>/lightrag/` and `spaces/` are set aside
  (`lightrag.openai-<date>/`, `spaces.openai-<date>/`); the new graph starts empty (clean slate).
- README, «Using the graph» and «How to extend»: the embedding model is the node's `embeddings`.

**Done when.** Insert and query work on a node with no OpenAI key.

**How it is proven.**
1. Door: the README's own example — insert «Pricing page» / «Stripe Checkout», then query «How does the site take payments?» → the
   entities come back with `llmCalls: 0` and `embedModel` MiniLM-L12. Negative control: «Fix a leaking kitchen faucet» with a threshold
   → `found: false`.
2. Files: the old folders set aside with their size untouched; the new vector files hold 384-number vectors.
