# 626-6 — The deep memory sends texts; no thinking call when `embeddings` is down

**What is built (in `Fractera/fractera-memory-starter`).**
- The phrases (`memory-said`), comments (`memory-feedback`) and cards of things go to the vectors element as TEXT; `lib/memory/node.mjs`
  no longer reads the OpenAI key for vectors.
- Before the thinking call (`lib/memory/think.mjs`), one check of `embeddings` `GET /api/embed-status`: not `ready` → no thinking call,
  the answer names the failing kind (`tool-unavailable`, the element's law), and the message stays in `messages_that_came_into_memory`
  as today. No queue, no timer (owner 2026-11-02: «мне кажется ты немножко начинаешь загоняться на очень редкие кейсы»).
- README: «Where a phrase goes», the vector line.

**Done when.** «remember» then «remind» works by meaning on a node with no OpenAI key (the thinking by Claude through the subscription).

**How it is proven.**
1. Door or Telegram: `POST /v1/remember` «the taxi from the airport cost 40 euro», then `POST /v1/recall` «how much was the taxi?» →
   the answer names 40 euro.
2. Journal: `memory-log.md` shows one thinking call; the phrase has its vector in `memory-said`; the graph space `memory` holds the facts.
   Negative control: `embeddings` stopped → `remember` makes NO `claude -p` call (the journal shows none) and answers `tool-unavailable`.
