# 626-4 — The core counts no vectors: agents' memory and element search send texts

**What is built (core).**
- `lib/agent-kit/memory/embed.cjs`: diary lines go to the vectors element as TEXT (`POST /vectors { text }`), questions as `query`
  (`POST /vectors/search { query }`); the OpenAI constant, `vectorsOf` over OpenAI and the key reading are removed.
- `lib/a2a/self-description.cjs`: the same — texts in, `query` to search; no `OPENAI_API_KEY` requirement.
- The ledgers (`data/node/memory/vectors.json`, the self-description ledger) rebuild through their existing model check — the model
  changed, so they start empty.

**Done when.** The main agent's associations and `npm run find` work on a node with no OpenAI key.

**How it is proven.**
1. `npm run memory -- vectors` → every diary line gets its vector; a Russian question finds its diary line by meaning.
2. `npm run find -- "<task words>"` puts the right element first on ten phrasings from the 603-5 set.
   Negative controls: `git grep "api.openai.com/v1/embeddings"` in the core → nothing; the same runs with no OpenAI key do not fail.

**Rests on.** 626-3.

**Not in it.** OpenAI uses that are not vectors: translations, `whisper-1`, fact drafts, social posts.
