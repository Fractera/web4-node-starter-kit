# 657-1 — the menu mode: compact by default, full by a click

**Repository:** `Fractera/web4-node-starter-kit` `main`.

## What is built

- `lib/node-menu-mode.ts` (server-only): `readMenuMode()` → `compact | full` from `data/node/menu.json` (no file or a bad value → `compact`),
  `writeMenuMode(mode)`.
- `app/api/node/menu-mode/route.ts` — `// @api the left menu of the core: compact or full`; `GET` → `{ ok, mode }`, `POST { mode }` →
  writes, `revalidatePath("/[lang]", "layout")`; roles architect/admin; a bad mode → 400.
- `_components/menu-mode-switch.client.tsx` — the «Настройка» row: «Компактная · Полная», the current one marked, a click posts and
  refreshes; read-only on the temporary address. Words en/ru in `_i18n/web4-drafts.i18n.ts`.
- `draft-menu.tsx` `withDrafts(menu, lang, path, mode)`: in `compact` — no zone «Нативные» (label, button, items, «Память»); `build`
  («Главный агент») out of «Основное»; no zone «Кастомные» label, no create button; root and each custom element a first-level item
  `{ label: <address>, icon: 'box', href: /<lang>/architect/<address>/preview }` with no children; the switch row first in «Основное».
  `architect-page.tsx` passes the mode.

## Done when

With no setting the owner's menu is compact as the owner described, and «Полная» brings back today's menu.

## How it is proven (named in advance)

1. **Eyes on the owner's node** (`http://localhost:24680/ru/architect`, 1440 and the 390 drawer): compact by default — the zones and items
   named above are absent, «root» opens its «Живой сайт»; a click on «Полная» → the native zone, «Главный агент», the custom zone with its
   button are back (**negative control: the same page with the other mode**); a click on «Компактная» → gone again; console errors 0.
2. **Data and door:** `data/node/menu.json` holds `{"mode":"full"}` after the click, `GET /api/node/menu-mode` answers it; `POST {mode:"x"}`
   → 400; through the temporary address the POST is refused and the file is unchanged. prebuild 0 (the guards above), `tsc` 0; CI green.
