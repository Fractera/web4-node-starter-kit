# 658-1 — the content factory: the main agent's skill, the instruction's lines, the tool's true word (core)

**Repository:** `Fractera/web4-node-starter-kit` `main`.

## What is built

- **Skill `.claude/skills/content-factory/SKILL.md`** (both natures; the form of `integrator`): why it matters — Claude.ai alone writes
  a good post; a node holds the whole loop — channels, voices, numbers, trends — and learns from every publication. The order, one link
  at a time, each after the person's yes:
  1. the person's channels and goal, in their words (which networks, blogs, boards, forums; what the publications are for);
  2. **the channels** — one element per channel when accounts, APIs and rhythms differ, one element with routes when they do not
     (`shape-the-need`); each with its own bot;
  3. **the author portraits** — an element «author portraits»: each author a route; the style taken apart into as many components as
     possible for an exact portrait (`study-for-element` for the analysis), then adapted to the person's product;
  4. **publications in the authors' voices** — a channel's agent asks the portraits element for a text in a voice over the API the two
     agents agree (`route-to-element`, i2i); the person approves a draft, or gives a standing yes for one channel and one rhythm;
  5. **the numbers** — each channel element reads its publications' statistics through the platform's official API into its own tables
     (654-1) and the deep memory; an analysis at a rhythm the person chose says what works where (the topic, the format, the hour, the
     voice) and proposes the next changes;
  6. **the scout** — an element that watches the chosen social networks, Telegram channels, YouTube and news portals through official
     APIs and feeds, catches a rising topic and proposes a publication in trend to the channel that fits;
  7. what the node lacks (an image or video generator, montage, animation) — an element of its own (`shape-the-need`); community skills
     for posting and analytics — `skills_find` first.
  **Laws:** every publication, every posting rhythm and every round of the scout after the person's yes, the price of a resident process
  named; official APIs, feeds and the person's own accounts only; a platform's rules (automation, spam, limits) read on its own pages,
  never told from memory (`provider-rules`, `npm run site-rules`); the followers' personal data never in git; nothing offered as working
  that the node cannot do today — no tool of the node posts by itself.
- **`shape-the-need`:** its content creator lines end with a pointer — the whole loop is skill `content-factory`.
- **`CLAUDE.md`** (the owner's word — the yes to this plan): §1 «Why a node is built» gets «**A content factory:** an element per channel,
  author portraits, publications in their voices, the numbers read back and a scout of hot topics.»; §3 the tool line «social posts by
  AI» → «social profile links from a phrase»; §4 one scenario line «**The content factory:** … — skill `content-factory`.»; §8 a
  pointer by the job; resealed (`npm run check:instruction -- --seal`).

## Done when

The main agent, given the content factory card's task, answers in the factory's shape and asks one question.

## How it is proven (named in advance)

1. **Guards, with negative controls:** `check-instruction` green with the new seal (the changed `CLAUDE.md` before the reseal → red);
   `check-instruction-skills` (the skill folder moved away → `✗ content-factory — named by CLAUDE.md`, then back → green);
   `check-skill-headers` (the count one higher); the broken-characters scan; CI three-os green.
2. **A live answer on the owner's node** after the delivery — one session of the main agent on the subscription, named before it runs:
   the card's task «Я хочу создать контент-завод…» → the answer names the channels, the portraits, the numbers and the scout, says that
   each is built after a yes, and asks one question; **negative control:** the integrator card's task → the integrator's order, not the
   factory's.
