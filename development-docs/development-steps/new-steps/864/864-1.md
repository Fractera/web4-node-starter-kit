# 864-1 — a name of an active server domain gets its certificate by itself

**What is built:** `lib/hosting/server-domain.mjs` — `uncertified(rows)` (required names with no usable certificate; also returned by
`domainState` as `uncertified`) and `namesToHeal(state, now)` (the domain on, the helper here, no certificate run at work, the name not
failed within the hour); `scripts/serve.mjs` — `healServerNames()` after `reapplyServerEdge()` at the start and at the top of
`agentsBackAfter` (the one end of every build), starting `name-up.mjs` detached; `scripts/dedicated-server/certs.mjs` — public DNS first
(`--dns-fresh` skips), the HTTPS check after (`--no-check` skips); `names-ready.mjs` passes both flags (it asked DNS, `name-up` checks).

**Done when:** on a live server with its domain on, a required name without a certificate is issued one at the node's next start or build
end, with no command typed.

**Proof, two planes named in advance:**
1. Code (`node scripts/hosting.test.mjs`): `namesToHeal` lists the born name; negatives — the domain off, no helper, a run at work, a
   failure ten minutes ago (and the same failure two hours ago is tried again), a covered name; the runner (dry) records
   `dns-check, nginx-apply … nginx-apply, https-check`, and with `--dns-fresh --no-check` neither; the wiring assertion: the heal sits after
   the edge at the start and at the top of the end of every build.
2. Live (aifa.dev, after Roma's push to Fractera and «Обновить сборку ядра»): `curl -sI https://market.aifa.dev/` → 200 class, no
   command typed on the server; negative before the update: curl error 35 (23:17 UTC 2026-11-27).
