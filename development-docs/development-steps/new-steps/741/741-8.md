# 741-8 — a server node can take its updates (found on the way, 2026-11-14 ~13:25 UTC)

**Found while proving 741-1:** the test server's own `node:update` (started the button's way: `spawn-free` → `node-update-run.mjs`)
stopped at «сливаю форк: 14 изменений» with `Committer identity unknown` and rolled back cleanly. Its history holds `87f5a242` (a letter
commit copied there by 737's move), which the fork does not have (`gh api …/commits/87f5a242` → 422), so `git merge --no-edit
origin/main` (`scripts/node-update.mjs:241`) needs a merge commit — and the node user `fractera` has no git identity: nothing in
`scripts/dedicated-server/*` or `scripts/launch.mjs` sets one. The computer never meets it — the person's own global identity commits
there. Every server whose main agent commits a letter (the agent's convention) would stop updating the same way. Belongs to 741: one more
behaviour that differs between a computer and a server.

**Done when:** a server node merges an update over its own commits, and its main agent can commit, without any personal identity.

## What is built
- `scripts/node-update.mjs`: when the repository has no `user.email` (`git config user.email` empty), the merge and any commit of the
  update run with `-c user.name="Fractera node" -c user.email=node@fractera.invalid` (`.invalid` is reserved and never delivers —
  RFC 2606); a configured identity always wins. No personal data enters git.
- `scripts/dedicated-server/install.sh`: one stage sets the same identity LOCALLY in the node folder (`git config user.name`,
  `git config user.email`) when none is configured — the main agent's own commits on the server work from the first day.
- The map of 741-7 gets the row «git identity: the person's on a computer, the node's neutral one on a server».

## Proof — two planes, named in advance
1. **Unit — `scripts/node-update-identity.test.mjs`** (in the prebuild chain): a temporary repository with a «fork» and a diverged local
   commit, `HOME` pointed at an empty folder (no global identity): the identity helper's merge succeeds and the merge commit's author is
   `Fractera node <node@fractera.invalid>`. **Negative control:** the same repository merged by plain `git merge --no-edit` fails with
   `Committer identity unknown` (today's server); and a repository WITH an identity keeps its own author.
2. **Live:** the test server receives the fixed core only by a fresh launch from the page (its old `node-update.mjs` cannot merge — the
   very defect); then `npm run node:update` there after one more push reaches `===NODE_UPDATE_DONE===`, and `git log -1 --format='%an
   <%ae>'` on a merge shows the neutral identity.

## Not in it
A GitHub identity for pushing from a server (GitHub tokens are a separate matter); rewriting the test server's history by hand.
