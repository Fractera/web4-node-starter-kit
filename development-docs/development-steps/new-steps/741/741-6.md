# 741-6 — the browser learns the place from the node, not from the address bar

**Done when:** every widget that behaves differently on a computer and on a server asks the node once per page and never decides by
`window.location.hostname` — and the owner's two wishes of 11:18 hold (the update banner on a server; the computer's top bar hides once
a server lives — D36).

## What is built
- A shared client reader `components/node-state/use-node-place.client.ts` — `useNodePlace()`: ONE `GET /api/node/place` per page
  (a module-level promise shared by every caller), returns `{ kind, source, foreign, mismatch } | null`; card in
  `components/node-state/parts.json` (`@part node-place-reader`). Prerendered pages stay static: the browser asks the door (the pattern
  of `server-place.client.tsx`).
- `components/hosting/server-place.client.tsx`: the view comes from `useNodePlace()` — `server` → `ServerLadder`, `home` → `ServerLaunch`;
  the quick-tunnel name no longer means «server» (today line 23). On the tunnel the launch view is read-only — its door already refuses
  writes there.
- `components/node-state/online-bar.client.tsx`, `temporary-address-alarm.client.tsx`, `dead-address-alarm.client.tsx`,
  `open-on-this-computer.client.tsx`: render nothing when `kind === "server"`; on `home` exactly as today.
- D36 (a): the launch runner (`scripts/dedicated-server/launch.mjs`, the «ready» stage) writes on the computer
  `data/node/server/launched.json` `{ "<ip>": { "domain": "<zone>", "readyAt": ISO } }` (no secret, no password); the online bar on
  `home` reads it through `GET /api/node/place` (field `launched: [{domain, readyAt}]`) and hides its temporary-address line while a
  launched server exists; «Домен и хостинг» shows «Ваш узел работает на сервере: https://<zone>» with the link. Removing the entry is
  740's danger zone (named there, not built here).
- `components/node-state/origin-notice.client.tsx` (the update banner): unchanged logic, proven on BOTH places — on a server it offers
  the server's own `node:update` (the owner's 11:18 question); `setOnTemporary` keeps using the hostname (it names the address, not the
  place — allowed by 741-7's guard list).
- `app/[lang]/(architectLayer)/_components/owner-band.client.tsx`: on a server reached through the SSH window it says «окно на сервер
  <ip>», not «этот компьютер» (`kind === "server"` with a loopback hostname).
- Texts only through the widgets' i18n files (`check:i18n`).

## Proof — two planes, named in advance
1. **Eyes (`npm run eyes`, screenshots looked at, console read):** this computer — `/ru/hosting/hosting` on localhost AND through the
   quick tunnel → the launch view on both (`data-block="server-place-own"` absent); the online bar present on localhost. The server
   through the window (741-5) → the ladder, no online bar, no temporary/dead-address alarm, the banner of `node:update` visible.
   **Negative control:** the same tunnel screenshot taken BEFORE the update (first action of this substep) shows `server-place-own` —
   kept in the summary.
2. **Wire:** `GET /api/node/place` through the tunnel and on localhost → `kind: "home"`; on the server through the window → `"server"`;
   the browser's network log of one page shows exactly ONE `/api/node/place` request although four widgets use it.
