# 741-5 — the SSH window comes back

**Done when:** `npm run server -- window --ip <IPv4>` gives the owner the server's panel at `http://localhost:<local port>` through the
node's pinned key, and the three texts that name the window are true again.

## What is built
- `scripts/server.mjs` verb `window --ip <IPv4> [--port <local>]`:
  - refuses without a pin for that IP (`readPins`, `lib/hosting/ssh.mjs`) — «сначала запустите сервер со страницы», never a password;
    a key the server does not accept → one line saying so (the launch page puts the key back), never a password prompt;
  - connects with the node key (`connect` without `password`), reads the server core's port from its `logs/runtime.json` (one `exec`,
    the same pattern as `launch.mjs:127`), opens a local listener on the first free port of 25680–25689 (outside the node's range
    24680–25679, never 3000 or ≥ 49152; `--port` overrides inside the same rules) and pipes each connection with `forwardOut` to
    `localhost:<core port>` on the server;
  - prints `===WINDOW=== http://localhost:<p>/ru` and holds until Ctrl+C or the SSH link drops, then says why it closed.
- `lib/hosting/edge.mjs`, `app/api/node/server/domain/route.ts`, `components/hosting/server-domain.i18n.ts`: the window is named with
  `--ip`, exactly as the verb takes it.
- The header comment of `scripts/server.mjs` lists the verb again (738 removed it with the move; the window is not part of a move).

## Proof — two planes, named in advance
1. **Unit (`scripts/hosting-launch.test.mjs`, it already runs an in-process ssh2 server):** the window against the in-process server:
   no pin → refused, a pin → a local port inside 25680–25689, a request through it reaches the fake core with `Host: localhost:<p>` and
   WITHOUT `x-fractera-edge`. **Negative control:** a busy 25680 → the next free port, never 24680–25679.
2. **Live (the test server):** `npm run server -- window --ip 213.199.61.7`, then `curl -s http://localhost:<p>/api/me` →
   `owner@machine` (no edge mark through SSH); the negative control — `curl -s -H 'Host: localhost' http://213.199.61.7/api/me` →
   000 (nginx 444): the same «localhost» from the internet is not the owner.

## Rests on
`lib/hosting/ssh.mjs` (`connect`, `exec`, pins, the node key), the server core's `logs/runtime.json`.

## Not in it
A button for the window on a page (the window is for the owner and the main agent; a page would need its own decision); Windows'
firewall prompts (the listener binds 127.0.0.1 only).

## Tasks this needs
No interface (a CLI verb). Parts born here: none.
