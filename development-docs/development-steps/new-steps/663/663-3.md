# 663-3 — the rule by the owner's thresholds, the proposal and the alarm (plan)

**Built.** `scripts/load-rule.mjs` (core; generalises `memory-by-free.mjs`, which becomes a thin call of it — the memory is one `auto`
element): above 1024 MB free — nothing; 1024–512 MB — a proposal to the main chat through the core's notice door (`/api/node/notice`) and
Telegram: which elements, why, what each costs (from 663-2); the person's yes → `npm run power -- <id> off` (the main agent, skill
`element-power`); below 512 MB — `auto` elements turned off by themselves, heaviest with least loss first, until above 512 MB, with a
message; the alarm when still below 512 MB with every `auto` asleep, or `never` elements alone leave less than 512 MB: «пора на сервер
мощнее» with the numbers and the consultation (§6). Runs: the core's start (`instrumentation.ts`, as 601), after a build, before an agent
session (`modes.cjs` bridge), after a calendar wake (663-4) — never a polling timer; dedupe 2 minutes. `--free`, `--dry` for the lab.
Elements turned off by the rule carry `powerAuto` and come back on by the same rule above 1024 MB.
**Done:** the node keeps itself above 0.5 GB without the person, and asks before cutting anything above it.
**Proven:** lab with `--free` 1500 / 800 / 400 on a copy of the registry — nothing / a proposal and nothing off (negative control) / auto
off in order, never untouched; the message text seen in the main chat on the node (a `--dry --notify` run).
**Not in it:** waking (663-4).
