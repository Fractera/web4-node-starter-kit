# 744-7 — one rule for every ladder, one rung open

**Done when:** no page decides which rung is open — the part does, by one rule (a rung opens only when every rung before it is done); one
rung is open at a time (the current), done rungs are one line each with what was done, locked rungs one muted line saying what opens them.

## Interface checkpoint (interface-design — written before the first line)
- Intent: the architect at his own computer bringing a server from an IP to a working domain, one decision at a time — a calm workbench
  checklist, not seven open cards.
- Hierarchy: the focal element is the current rung's body; done rungs demote to one line (check in `primary`, summary `muted-foreground`);
  locked rungs to a muted line with a lock — three tiers by weight and colour at one size.
- Palette: tokens only (`primary`, `muted-foreground`, `border`, `card`); no new colour. Depth: borders only — one bordered list, rows
  separated by its border, not a card per rung. Typography: `H3 variant="ui"` for the open rung, the trigger at body size weight 500,
  summaries `Small`. Spacing: the panel's density (p-4 rows, gap-3 inside a body).

## What is built (D46, D47)
- `lib/hosting/ladder-rule.mjs` (pure): `openOf(rungs)` and `currentOf(rungs)` — imported by the part and by the test.
- The part `ladder-step` (`components/hosting/ladder-step.tsx`, card updated): `Ladder({ rungs: [{ id, title, done, summary, body }] })` on
  shadcn `Accordion type="single" collapsible`; value = the current rung, following it when a rung becomes done; a locked rung is a
  disabled item with the grey line; a done rung can be opened to look back (one at a time). `LadderStep`/`LadderLocked` removed when no
  user remains (the computer's domain ladder keeps them until 745, D47).
- `server-launch.client.tsx`: the `opens` table removed; rungs in order; install's predecessor is the domain (D46); recheck's predecessor
  is install + the server node answering. `server-launch-domain.client.tsx`: the same part for the sub-ladder.

## How it is proven
1. **Rule plane, with a negative control:** `scripts/ladder-rule.test.mjs` — a rung after an undone one is locked; all done → the last is
  current; a source scan refuses a file under `components/hosting/` that computes `opens`/`open =` for a ladder itself (a planted copy is
  refused).
2. **Eye plane:** `npm run eyes` on the launch page with no server → only step 1 open, steps 2–7 locked lines (png); the owner's Chrome with
  the test server → one rung open, the others one line each; keyboard: Tab to each trigger, Enter opens a done rung and closes the current.
