# 744-2 — one rule for every ladder

**Done when:** no page computes which rung is open; the ladder part takes an ordered list of rungs with `done` and opens a rung only when
every rung before it is done — and the launch page's install opens only after its domain.

## What is built
- `components/hosting/ladder-step.tsx` (part `ladder-step`): `Ladder({ rungs: [{ id, title, done, summary, body }] })` — `open(i) =
  rungs.slice(0, i).every(r => r.done)`; `current` = the first open rung not done (or the last rung when all are done). Extra conditions
  of a rung (e.g. «the server node answers» for recheck) go into that rung's `done` of the rung BEFORE it, never into a side table.
- `server-launch.client.tsx`: the `opens` table removed; the seven rungs passed in order; install's predecessor is the domain.
- `server-launch-domain.client.tsx`, `server-ladder.client.tsx`, `server-ladder-end.client.tsx`, `domain-ladder.client.tsx` (D47): the
  same part, their own `open` computations removed.
- A test `scripts/ladder-rule.test.mjs` over the part's pure `openOf(rungs)`: a rung after an undone one is locked; all done → the last
  current; and a source scan: no file under `components/` computes a ladder's `opens`/`open =` itself (the planted copy refused).

## How it is proven
1. **Rule plane, with a negative control:** the test green; a planted `const opens = …` in a scratch copy of `server-launch.client.tsx` →
   refused naming the file.
2. **Eye plane:** `npm run eyes` on the launch page with a server whose step 3 is not done → step 4 is a locked line (png in logs/eyes).
