# 744-4 — step 3 shows the server's truth

**Done when:** the launch page's step 3 for a server shows the domain and the way the server already knows, counts as done exactly when a
domain and a way are chosen, and step 4 opens only then.

## What is built
- One domain record: `launch.mjs` `readState` — when `/root/.fractera/domain.json` is absent and the server node's mark
  (`data/node/server.json`) has a `domain`, the page's record is written from it once: `{ domain, way: domainWay, from: "server", at }` —
  so every action (detect, way, dns, records) reads one source. ✗ Measured: on the test server the record was absent while the mark held
  `aifa.dev` / `migrate` («Только у регистратора»).
- Step 3 done = a domain and a way other than «Нет доступа» (D46 strict); its summary names the domain, the way in the person's words
  and where the choice came from («записано на сервере 13 ноября»); the detect runs by itself for a known domain (as today).
- The sub-ladder (domain → where → who → records) is the same accordion (744-3); its records rung shows what to write; the DNS check stays
  step 5's work («Повторная проверка записей»), so step 3 does not wait for DNS.

## How it is proven
1. **State plane, with a negative control:** on the test server `readState` → `state.domain` = `{ domain: "aifa.dev", way: "migrate",
   from: "server" }` and `/root/.fractera/domain.json` exists with it; a scratch state with neither record → step 3 not done, step 4
   locked (the 744-2 test with this page's rungs).
2. **Eye plane:** the launch page on the test server: step 3 closed as done with «aifa.dev · Только у регистратора», step 4 open (png).
