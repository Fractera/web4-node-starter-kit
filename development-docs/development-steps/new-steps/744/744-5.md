**Done when:** step 3 of a server that already has a domain shows it and its way as done (one line: «aifa.dev · Только у регистратора ·
записано 13 ноября»); a new server's step 3 asks, in this order, «Есть ли у вас доступ к регистратору домена?» and, only on «нет», «Есть ли
у вас доступ к Cloudflare?»; the answers lead to the records rung; step 3 is done when a domain and a way are known (D46).

## Measured before
The page reads only `/root/.fractera/domain.json` (absent on the test server) while the mark holds the domain and way; the question is one
question with four options («Где вы можете менять DNS-записи…»).

## What is built
- One domain record: `launch.mjs` `readState` writes the page's record from the server node's mark when the page has none —
  `{ domain, way: domainWay, from: "server", at }`; every action reads that one record.
- The «who» rung becomes two questions (`server-ladder-steps.client.tsx` `WhoStep`, words in `server-ladder.i18n.ts`, en + ru):
  registrar? yes → way `dns`; no → Cloudflare? yes → way `cloudflare`; no → way `none` with today's instruction for the person who has the
  access. The detection «where the records live» (WhereStep) stays first and still informs the answer (a domain whose DNS is at Cloudflare
  while the person has only the registrar → way `migrate`, its words as today).
- Step 3's summary for the accordion (744-7): domain · way in the person's words · where it came from.

## How it is proven
1. **Flow plane, with a negative control:** a dry launch test (`hosting-launch.test.mjs` with the local test SSH server): «registrar: no,
   Cloudflare: yes» → way `cloudflare` recorded; «registrar: no, Cloudflare: no» → `none`, step 3 NOT done, step 4 locked.
2. **Eye plane:** the owner's Chrome — the test server before the clear: step 3 closed as done «aifa.dev · Только у регистратора»; after the
   clear and the installation (744-9): the two questions in order, one at a time (screenshots into `logs/eyes/`).
