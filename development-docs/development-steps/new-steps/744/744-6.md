# 744-6 — never «available» before every certificate and the final check

**Done when:** the words that tell the person the server can be used («Ваш сервер готов», links to the site and panel, the computer's
«launched» mark) appear only after a final check that passed for every required name: a valid certificate, HTTPS answering from the
internet, and sign-in leading to `auth.<zone>`.

## Measured before
`markLaunched` and «Ваш сервер готов» sit in the last rung, which opens after the certificates — right by construction, but held by no rule
and no test; the per-rung `opens` table could be changed by any edit (as 738 did for «install»).

## What is built
- `lib/hosting/final-check.mjs` (pure, tested): `finalCheck(state)` → `{ ok, missing: [{ host, what: "cert"|"https"|"signin" }] }` over the
  server's rows (`state.core.rows`), the HTTPS check and the sign-in check.
- The last rung opens on `finalCheck().ok` only; its body lists what is missing otherwise; `activate`/`signin` in `launch.mjs` refuse
  (`not-ready`, with `missing`) before `markLaunched` unless `finalCheck` passes on the server's fresh state.
- The guard `scripts/check-ready-words.mjs` (in `prebuild`): the «ready» keys of `server-launch.i18n.ts` (`ready.done`, `ready.links`,
  `ready.site`…) are rendered only by the final rung's component — a use anywhere else is refused.

## How it is proven
1. **Rule plane, with negative controls:** `scripts/final-check.test.mjs` — all names with certs + HTTPS + sign-in → ok; one name without a
   cert → not ok, named; HTTPS failing → not ok; the runner's `activate` on such a state → `not-ready`, `launched.json` unchanged.
2. **Live plane:** 744-9 — the last rung stays closed while a certificate is missing (screenshot), opens after the check passes.
