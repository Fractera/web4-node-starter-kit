# 744-3 — access for one day

**Done when:** step 1 needs the real root password unless this browser holds a key for that server younger than 24 h; the key's line on the
server carries `expiry-time` computed by the server's own clock; the browser keeps the key as an HttpOnly cookie (≤ 24 h); no server key or
password exists in the node's folder; at the deadline the server itself refuses the key.

## Measured before
11 actions by the persistent `data/node/server/id_ed25519`; the test server's `authorized_keys`: `fractera-node` (no expiry) + 7 foreign;
probe 1: future accepted / past refused / «Z» refused on 8.6; server CET vs computer WET; GTM on the panel when analytics is on.

## What is built (D44, D45)
- `lib/hosting/ssh.mjs`: `openVisit({ host, port, password, hours = 24 })` — `readableKeyPair()` in memory; a password connection; on the
  server: `D=$(date -d "+${hours} hours" +%Y%m%d%H%M)` (its own clock and zone), remove this node's earlier lines (`fractera-node`, expired
  `fractera-visit`), append `expiry-time="$D" ssh-ed25519 … fractera-visit <ISO>`; a second connection by the new key must succeed, else the
  line is removed and the step fails with `key-refused` (an OpenSSH < 8.2 or a broken option fails closed). Returns `{ privateKey, deadline }`.
  `ensureKeyPair`, the key files and their pin of the key comment go; host-key pins stay.
- `scripts/dedicated-server/launch.mjs`: stdin is JSON `{ password?, key? }`; `connect` with a password → `openVisit`; every other action
  → `key`; no or refused key → `need-password`. Action `close`: removes the visit line now. `remote.mjs`/`window.mjs` take the key from
  their caller.
- The door `app/api/node/launch/route.ts`: on connect it receives the key from the runner and sets the cookie
  `fractera-visit-<ip>=<base64url key>; HttpOnly; SameSite=Strict; Path=/api/node/launch; Max-Age=<seconds to the deadline, ≤ 86400>`; the
  JSON answer carries the deadline, never the key; every action reads the cookie and passes it to the runner by stdin; `close` clears it.
- `probe.sh`: reports OUR access — `{ visit: [<deadlines>], legacy: <fractera-node present>, others: <count> }`, never a foreign key.
- The page, step 1: IP and password; done line «Доступ до HH:MM (24 ч)» + «Закрыть доступ»; a provider without password login named.
- The SSH window (741-5): opened from the page through the door (cookie), not from the CLI with a stored key (D45).

## How it is proven
1. **Server plane, with a negative control:** after step 1 the probe shows `visit: [<deadline ≈ now+24h server time>]`, `legacy: false`;
   a visit opened with `hours` = 1/60 (the runner's `--minutes 1`, test only) — after 90 s an action with that cookie → `need-password`, the
   server's `auth.log` «Authentication refused: … expiry», while a minute earlier the same key worked.
2. **Computer plane:** `ls data/node/server` → no `id_ed25519*`; `grep -r` of `data/` and `logs/` finds neither the password nor the key;
   the owner's Chrome DevTools → the cookie is HttpOnly and `document.cookie` does not show it (screenshot); `scripts/hosting-launch.test.mjs`
   updated: connect with the password returns a deadline and sets no key file; an action without the cookie → `need-password`.

## Not in it
Typing a password by an agent (never); SSH keys of providers.
