# 744-3 — one rung open: the accordion

**Done when:** every ladder of the node shows exactly one open rung — the current one; a done rung is one line (its check, title, what was
done); a locked rung is one muted line saying what opens it; the person may open a done rung to look back, which closes the open one.

## Interface checkpoint (interface-design, before the first line)
- Intent: the architect at his own computer bringing a server from an IP to a working domain; one thing at a time, nothing to guess —
  a calm workbench checklist, not a wall of cards.
- Hierarchy: the focal element is the current rung's body (open, full width); done rungs demote to a single line (Small, muted summary,
  primary check); locked rungs to a muted line with a lock — three tiers by weight and colour, one size.
- Palette: tokens only — `primary` for the current number and the checks, `muted-foreground` for summaries and locked lines, `border` for
  the separation between rungs; no new colour.
- Depth: borders only (the panel's language): one bordered card around the ladder, rungs separated by its rows — not seven cards.
- Typography: `H3 variant="ui"` for the open rung's title, the trigger line at the body size with weight 500, summaries `Small`.
- Spacing: the panel's density (p-4 rows, gap-3 inside a body).

## What is built
- The part `ladder-step`: `Ladder` renders shadcn `Accordion type="single" collapsible` (`components/ui/accordion.tsx`), value = the
  current rung; when `current` changes (a rung becomes done) the value follows; a locked rung is an `AccordionItem disabled` with the grey
  line; each rung supplies `summary` for its closed line. `LadderStep`/`LadderLocked` stay only if a user remains (else removed with their
  card entries).
- Summaries: server «213.199.61.7 · доступ до HH:MM»; check «Сервер подходит · Fractera <ver>»; domain «aifa.dev · Только у регистратора»;
  install «Установлено: <ver>»; recheck/certs/ready from their own state; sub-ladder rungs likewise.
- Texts through the ladder dictionaries (`server-launch.i18n.ts`, `server-ladder.i18n.ts`), en + ru.

## How it is proven
1. **Eye plane:** `npm run eyes` — the launch page connected to the test server: one open rung, the rest one line each (png); the keyboard:
   Tab reaches each trigger, Enter opens a done rung and closes the current one; both themes.
2. **Guard plane:** `check:shadcn-parts`, `check:typography`, `check:i18n`, `check:parts-map`, `check:contrast` green; the 743-7 hook lets
   the files through only with the three skills loaded (the session journal shows them).
