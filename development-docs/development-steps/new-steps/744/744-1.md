# 744-1 — the proxy in two files

**Done when:** the computer's routing and the server's routing live in two separate files, one small entry chooses between them once by the
place record, and each file's behaviour table passes on its own.

## What is built (D51)
- `proxy.ts` — the entry Next.js requires, ≤ 40 lines: reads the place (`lib/hosting/place.mjs` `placeKind`, once per process) and calls
  `computerProxy(request)` or `serverProxy(request)`; a «foreign»/«mismatch» record (741-2) is routed as the record says and logged.
- `proxy/common.ts` — what both do: the cross-site wall (744-2), languages and the `/[lang]/` prefix, static assets, the agent doors' key.
- `proxy/computer.ts` — localhost owner without sign-in; the temporary address read-only (`temporaryAddressPage`, the 403 for doors);
  no own domain → the tunnel name.
- `proxy/server.ts` — no tunnel; the bare IP → its card and `/api/health` only; the own domain → sign-in everywhere; `localhost` only
  through the SSH window (741-5).
- Every place-dependent branch now in `proxy.ts` and in `lib/auth/*` (741-3's second wall) is moved to the file of its place; the guard
  `check:place-readers` (741-7) learns the two files and refuses a place check in `proxy/common.ts`.

## How it is proven
1. **Table plane:** `scripts/proxy-split.test.mjs` — the 741-7 map's 25 rows (computer vs server) replayed against each file with built
   requests (host, path, headers): each row gives the answer of its place; a planted computer branch in `proxy/server.ts` (localhost owner
   without sign-in) → the test fails (negative control).
2. **Live plane:** this computer after the update — `curl localhost:24680/ru/hosting/hosting` 200, the tunnel name → read-only, a door
   through the tunnel → 403 `temporary-address` (as today, `probes/csrf.sh` style); the server after 744-9 — bare IP → the card, the own
   domain → sign-in.

## Rests on / not in it
Rests on 741 (the place record, the map). Not in it: new behaviour of either place — only the split.
