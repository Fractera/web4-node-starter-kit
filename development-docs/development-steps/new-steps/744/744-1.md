# 744-1 — access for one day

**Done when:** no server key exists in the node's folder; step 1 of a visit takes the real root password, installs a fresh key whose line
in root's `authorized_keys` carries `expiry-time` ≤ 24 h, and hands the private half to the browser, which keeps it in `localStorage` with
the same deadline; every later action of that visit is signed by that key; at the deadline the server itself refuses it.

## What is built
- `lib/hosting/ssh.mjs`: `visitKey({ host, port, password, hours = 24 })` — a fresh ed25519 pair IN MEMORY; connects by the password;
  removes this node's earlier lines (`fractera-node`, `fractera-visit …`) from `authorized_keys`; appends
  `expiry-time="<YYYYMMDDHHMM>Z" ssh-ed25519 … fractera-visit <host> <ISO deadline>`; returns `{ privateKey, deadline, fingerprint }`.
  `connect()` takes `privateKey` from its caller; `ensureKeyPair` and the key files are removed (D45).
- `scripts/dedicated-server/launch.mjs`: stdin is JSON `{ password?, key? }`; `connect` with a password → `visitKey` → answers the key and
  its deadline; every other action uses `key` from stdin; no key and no password → `need-password` (step 1 asks again); a refused key
  (expired, removed) → `need-password` too. Action `close`: removes the visit line from the server now.
- The door `app/api/node/launch/route.ts`: passes `{ password, key }` to the script by stdin (never in argv, never logged); answers the key
  once, on connect.
- The page: `localStorage["fractera-launch-key:<host>"] = { key, deadline }`; an entry past its deadline is deleted on read; every action
  sends the key in the POST body; step 1's done line says «доступ до HH:MM (24 ч)» and offers «Закрыть доступ» (action `close` + delete).
- The 741-5 SSH window (`npm run server -- window`) and the 743-5 bridge go through the visit key (the page holds it); the migration of
  D45 runs on the first visit of each server: the old `fractera-node` line removed.

## How it is proven
1. **Server plane, with a negative control:** after step 1 `grep fractera-visit /root/.ssh/authorized_keys` shows `expiry-time=` at the
   deadline; a visit made with `hours` set to 1 minute (test hook of the script, `--minutes 1`) — after 90 s an SSH login with that key is
   refused by the server (`Permission denied`), the same key a minute earlier was accepted.
2. **Computer plane:** `ls data/node/server` holds no `id_ed25519`; the browser's `localStorage` holds the entry with a deadline ≤ 24 h
   (read in the owner's Chrome); `grep -r` of the node's `logs/` and `data/` finds neither the password nor the key.

## Not in it
Passwords typed by an agent (never); providers without password login (named on step 1: «сервер не принимает пароль — нужен вход по
ключу провайдера»).
