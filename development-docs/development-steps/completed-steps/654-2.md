**What and how.**
- **Storage** `lib/data-store/media.mjs`: late columns `owner` (default `node`) and `visibility` (default `public`) on `media`, `owner` on
  `icon_sets` — everything kept before stays the node's and public, as it was served. `sees` / `owns` / `mayRead`: an element key
  (`req.element`) lists, reads and thumbnails its own records and the node's public ones; changes, trims and deletes only its own; another's
  answers 404, the same as a missing one; an upload with it is its own, private on `visibility=private`. **A private file leaves only when
  asked by name** — `GET /media/:id/file?private=1` (and `/thumb`) with the owner's key or the node key, `Cache-Control: private, no-store`
  — so the public route `/api/media/<id>/file` of every installed element and of the core (the node key, no flag) stopped serving private
  files with no release of the elements. The node key sees all, `?owner=<id>`, `PATCH { owner }`. Icon sets: an element's own and the
  node's; the node's current set never becomes an element's, an element's never becomes everyone's. `app.mjs`: the element key opens
  `/media/*` and `/capabilities`.
- **Memory** `lib/memory/fractera/objects.ts`: every object uploaded `visibility=private`; `open` and `fileOf` read `?private=1`;
  `markOwnPrivate` marks the objects kept before (every `object_id` of its rows, all spaces) — once at the server's start
  (`instrumentation.ts`, not awaited) and, while that has not finished, at the next door call (`door.mjs`); no timer; a storage without
  `visibility` leaves it for the next call. README of storage «Whose file», memory README line.
