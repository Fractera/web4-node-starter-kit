# 646 — the update banner on the temporary address

**Commit:** `ad533d76` in `Fractera/web4-node-starter-kit` (main). One-file fix (and its dictionary), no plan window.

**The owner, verbatim:** «если я нажимаю проверить снова … этот баннер просто исчезает как будто нажимаю кнопку скрыть … у меня нет никакой
возможности при помощи кнопки обновить сборку».

**Cause, measured.** POST `/api/node/update {action:"check"}` on the trycloudflare address → 403 `{"ok":false,"reason":"temporary-address"}`
(`proxy.ts`); `origin-notice.client.tsx` did `setD(body)` → no `fork` → `return null`. On localhost the same POST → 200.

**What.** A non-ok answer keeps the state and names the reason; on a temporary hostname «Открыть на этом компьютере»
(`OpenOnThisComputerButton`) and a line that checking and updating work only on this computer, instead of «Проверить снова».

**Proofs.**
1. `eyes --top` on https://sections-horn-endorsement-wines.trycloudflare.com/ru/passport/how-it-works: `[data-node-update]` «виден»,
   `[data-open-on-this-computer]` «виден» ×2, `[data-node-update-check]` — not found (negative control: the button is gone there); the
   screenshot looked at. The one console error is the expected 403 of a refused door.
2. The served page on both addresses carries «Проверить форк и обновить узел можно только на этом компьютере» (1 match each).

**Mistakes.** The owner's report «обновил узел» was taken first, but no update had run (no record after 20:23): his clicks were on the
temporary address, where the old banner vanished. I ran `node:update` myself.

**On the way, not fixed:** on the temporary address «Обновить сборку ядра» is active though its page is read-only.

**Evolution of skills.** Nothing beyond 647.
