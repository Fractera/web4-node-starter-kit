## What was built

- **The definition, one text everywhere:** a tool solves a task with its own interface and does not know which page it stands on;
  tools nest (an image-editing form = a modal window holding a crop, a voice input and a call to an image technology — and the form is a
  tool too); a combination is a tool kept as a recipe — its glue and its parts by id and version; not tools: primitives, sections,
  widgets (bound to their page, they hold tools). Where it lives:
  - the panel glossary `app/[lang]/(architectLayer)/_i18n/architect-home.i18n.ts` — «Tool», «Section», «Widget», en and ru (54 words);
  - CLAUDE.md §7 «Tool», resealed (`982fc7d7f3d9`);
  - `use-tools` of the core and of the three templates (in the templates it replaced «will a second caller want exactly this thing? Yes
    — a tool» — the very rule that kept a tool from being born);
  - the element instruction's sealed source `lib/instructions/element/element-instruction.src.md` — a bullet «What a tool is», common to
    every template, regenerated into custom, native and root;
  - the Tools tab's accordion (en, ru).
- **The check at birth:** the gate `.claude/hooks/parts-gate.mjs` asks the three questions in every refusal (a page's look → section;
  bound to this page → a widget that holds tools; a task with its own interface → a tool, even when one place needs it today; its parts
  found or born first) and lets a file under `_tools/<id>/` be born only after its card. Elements run the core's own hook file
  (`element-isolate.mjs`, `PARTS_HOOK`), so they get it with the node update.
- **Before the code:** «Tasks this needs» in the core's plan template (`use-development-steps`) and in the elements'
  (`use-development-docs` of the three templates).
