## What was done and how

- **The owner's words** (2026-11-10): «избавиться от использования слова блоки и начать использовать слово секции … сможем более чётко
  переписать документацию»; the README files of the main repository and of every folder must not conflict; «сделать скрипт который
  просто выполнится автоматически исправит все остальные элементы».
- **The migration script** `scripts/migrate-sections.mjs` with its map `scripts/migrate-sections.map.json` (the map is the document of
  every rename): `npm run migrate:sections` shows the plan, `-- --apply` does it and writes `development-docs/reports/migration-sections-
  <date>.md`. It splits each section of the old set into `components/sections/<kind>/` (`index.tsx` with `Section` and `Shape`,
  `markdown.ts` cut out of the old switch, `README.md`), writes the set `components/sections/index.ts` (`SectionItem` derived from it — a
  folder without `markdown.ts` does not compile), renames kinds `block-*` → `section-*` and the page's list `blocks` → `body` in data and
  code, names (`PageItem`, `KindSet`, `ItemData`, `renderPage`, `pageToMarkdown`, `itemKey`) and imports, deletes the dead
  `lib/content/blocks/inline.tsx`, and lists the element's own prose for its agent.
- **The template** migrated by the script from v0.3.185 (717-2a), then its words by hand (717-2b): the instruction regenerated from the
  core's source, modes, the skills index and skills (stale facts fixed — no admin «Blocks» page or drawer item since 706; a new section
  brings its own `markdown.ts`), every README of the branches, comments of code and guards; small renames (`panels.tsx`,
  `DesignEditorPanel`, `keepOpen`, CSS `rules`, `typeBody`, `robots-closes-language`, `data-create-kind` / `data-edit-code`); the port
  «block» is a range in prose; the A2A card's catalog skills find, give and take sections.
- **«Block» keeps one meaning** — the address of a container: `data-block`, `#block=`, `bid`, `npm run blocks:ids`, the highlight and its
  `fractera:block` message to the core. Kept on purpose: CONFIG's `blocks.heroOneWidth` (renamed only together with the core's CONFIG —
  a named debt), the account action «Block / Unblock», Tailwind's `block`, shadcn's `registry:block`, the owner's quotes.
- **The guard** `check:words` = `npm run migrate:sections -- --check` (in `prebuild`): the script's own scan, no second list; it refuses a
  section-sense «block» and anything the migration would still change. `check:page-sequence` refuses a page still on the key `blocks`.
- **The split, as built:** the script carries an element's own code and data; the template-owned files reach an existing element by
  the template's rollout (`npm run template -- rollout custom <tag> <paths>`).

## Proofs (two planes, negative controls)

1. **Machine:** the workshop — `tsc exit 0`, `npm run build` exit 0 with `===PAGE_SEQUENCE_OK=== страниц: 37; секций в наборе: 3,
   типографики: 12`, `===TREE_OK=== … 521 путей`, `===WORDS_OK===`; CI three-os of `c8c1c72` — success (7m27s).
2. **Behaviour:** v0.3.185 and the migrated copy built and started on scratch ports; `/en`, `/ru`, `/en|ru/privacy`, `/en|ru/terms`,
   `/en/cookies`, `/en/guest`, their Markdown twins, `/llms.txt`, `/llms-full.txt` — after removing scripts and asset hashes the only
   differences are the `data-kind` values and the scratch port inside `og:image`.
3. **Negative controls:** a page naming `block-faq` — `===PAGE_SEQUENCE_FAILED===`, exit 1; a section folder without `markdown.ts` —
   `tsc` exit 2 `TS2307: Cannot find module './markdown'`; a README line «Add the blocks of this page here.» — `check:words` exit 1 naming
   `README.md:38`; a page back on the key `blocks` — `check:words` exit 1 and `check:page-sequence` exit 1 «старый ключ «blocks» — тело
   страницы теперь «body»»; each restored — green.
4. **An element's own section:** a v0.3.185 copy with a section written the old way in four places (`block-hero-demo`: component,
   set line, union line, switch case) and a page using it — `npm run migrate:sections -- --apply` moved it into
   `components/sections/section-hero-demo/` with its `markdown.ts`, its set line, the page on `body` and `section-hero-demo`.
   Then `tsc` exit 0, `npm run build` exit 0 (`===PAGE_SEQUENCE_OK=== страниц: 38`, four sections in the set); started on a
   scratch port, `/en/demo` draws `data-kind="section-hero-demo"` with its words, and `/en/demo/index.md` and `/ru/demo/index.md` carry
   «# A first screen of our own» / «# Свой первый экран» from the section's own `markdown.ts`.

## Mistakes

- The first run renamed «blocks» in words people read (`*.i18n.ts`) and inside file paths — the script now leaves both to the eye.
- A relative import the script itself wrote was re-resolved from the old place; `heroBlock` → `hero` collided with a name in scope; the
  kind rule required a letter after `block-` and missed `'block-'`, `block-*`, `block-<name>`; «Яблоко» matched «блок» — each found by a
  build or a scan of the copy, each taught to the script.
- The report quoted Russian outside «…» and the template's own documents guard stopped the build — rightly; quoted now.
- I corrupted the map by cutting its JSON at the first «]» (inside a pattern) — restored from the commit, written by a parser since.
- The words guard first passed a spoiled page key: it scanned the migration's in-memory result. It now fails on any change the
  migration would still make. Found on the way: `check:page-sequence` skipped a page without `body` silently (drawn empty) — closed.
- The plan said every hand fix a script could do is taught to the script first; for the template-owned prose and small renames I did
  not — their road to the elements is the rollout, recorded in the plan.
- My letter before the reset called the weekly 99 % the node's; it was root's own login (`own-root.json`).
