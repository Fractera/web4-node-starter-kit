## What was done
- `findInCatalogFile` counts the query once and searches the own index first at its own threshold, then the catalog at 0.60; an own
  skill stands first, marked `own`, and is not repeated among the catalog's cards. The own skills answer even when the catalog is not on
  the node yet. An own index counted by another model is never compared with the query — named in `ownNote`; the catalog still answers.
- Every reader follows: `skills_find` (the text opens with «The person's OWN skills — they kept these themselves; offer them FIRST»),
  the core's door (so the elements and memory's `findSolution` get `own: true` first), `npm run skills -- market`.
- **The priority is the lower bar**, measured, not guessed — `social` kept, 10 fitting and 10 unrelated requests
  (`fixtures/own-20.json`):
  ```
  threshold 0.4: inside 9/10, leaks 0/10     (the highest unrelated 0.368 — too close)
  threshold 0.45: inside 8/10, leaks 0/10    ← chosen
  threshold 0.5: inside 8/10, leaks 0/10
  threshold 0.55: inside 7/10, leaks 0/10
  threshold 0.6: inside 6/10, leaks 0/10     (the catalog's own bar)
  ```
  The two misses: «придумай цепляющий первый экран для поста в X» 0.41, «как увеличить охват в TikTok» 0.33.
