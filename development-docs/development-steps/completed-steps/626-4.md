## What was done (core, the commit of this summary)
- `lib/agent-kit/memory/embed.cjs`: the OpenAI constant and `vectorsOf` are gone; a diary line goes to the vector element as text
  (`POST /vectors { text }`), a question as `query` (`POST /vectors/search { query }`); the vector element counts both through the node's
  `embeddings`. `kind()` asks the vector element's model and size EVERY time (one local call) and empties the ledger when the model is
  another one — it used to keep the first answer forever, so an OpenAI-era ledger would have kept claiming vectors in a set-aside store;
  `configured: false` (embeddings down) throws, so the callers fall back to words.
- `scripts/memory.mjs` (`npm run memory -- vectors`) and `lib/agent-kit/memory/recall.cjs`: `kind()` before the ledger is read.
- `lib/a2a/self-description.cjs` (`npm run find`, the duplicate check of `create`): no OpenAI key needed; an element is indexed as its
  whole description plus short pieces (`indexPieces`: the name with the short description, the long one by about 45 words, the role, every
  skill), and its score is 0.3 × the whole + 0.7 × the best piece — MiniLM reads 128 tokens, and one vector of a 6,000-character
  description lost most of it.
- `scripts/main-agent-cli.mjs`: `FIND_MIN` (= `DUP_MIN`) 0.21 → 0.25, measured on MiniLM; the machine fact the agent tells («what goes
  out») no longer names vectors.
- Comments of `record.cjs` and `recall.cjs` follow; `MIN_SCORE` of the associations stays 0.4 (measured below).

## Proof

`env -u OPENAI_API_KEY`): `embeddings` v0.1.1, vectors v1.2.0, data v2.2.0 on spare ports; the core copied with its registry pointing at
that data element; the passports and routes of the node's 13 elements copied read-only from the owner's node; a test diary of 10 lines.
1. **Memory:** `npm run memory -- vectors` → `===MEMORY_VECTORS=== 10 line(s) got a vector, counted on this computer; 10 line(s) have one
   now.` (the ledger: `paraphrase-multilingual-MiniLM-L12-v2`, 384). The associations of the main agent: «сколько стоило такси?» → `how:
   meaning`, 0.695 «Такси из аэропорта стоило 40 евро, я заплатил наличными». Seven questions in Russian and English: the right line first
   in 6 (the seventh: the agent's reply of the same exchange first, 0.490).
2. **Find:** `npm run find` with ten phrasings in Russian (a set of its own, not the calibration one) — the right element first in 9:
   stripe 0.52, auth 0.40, memory 0.47, storage 0.59, data 0.49, graph 0.54, design 0.61, blocks 0.71, root 0.54; the miss — «найти похожие
   тексты по смыслу» → memory 0.44 (the deep memory finds by meaning too), embeddings 0.32 third, vectors 0.30 fourth.
   Negative controls: `git grep "api.openai.com/v1/embeddings"` in the core → nothing; a ledger set back to `text-embedding-3-large` →
   emptied and all 10 lines counted again (this control failed first — see «Mistakes»); `embeddings` stopped → the associations answer
   `how: words`, nothing breaks.

## Measured — the thresholds
- `FIND_MIN`: 20 intents and 6 jobs the node lacks (the method of 603-2; the 603-5 set is not in this repository). One vector a
  description: the right element first 19 of 20 but at 0.118–0.572 under the absent jobs' 0.284; pieces alone — 15 of 20 first, 17 of 20
  above; the mix — 17 of 20 first, right 0.203–0.638, absent 0.205–0.304. No clean gap: 0.25 lets 19 right elements of 20 and 4 absent
  jobs of 6 through — a wrong candidate costs the agent a card to read (and `create` a `--different`), a missed one can birth a duplicate.
- `MIN_SCORE`: the right lines 0.372–0.705, the unrelated questions' best 0.107–0.383 — the gap closed; 0.4 kept (no false hit here, the two
  weakest paraphrases missed) and re-measured on the live diary in 626-8 (a value is never tuned on the set it is proven on).

## Limits
MiniLM separates the elements worse than OpenAI did (2026-10-26: 29 of 30 first with a clean gap 0.193–0.239): 17 of 20 and 9 of 10
first, no clean gap. Better short descriptions in the passports help it most (the head piece carries the score). The live node gets all
this with 626-8.

## Mistakes
- `kind()` trusted the first model it had seen — found by reading the code before the stand; both ledgers would have missed the switch.
- The model-change control failed: `memory vectors` and `recall` read the ledger before `kind()` could empty it, so nothing was counted;
  fixed where it happened, the control passed on the second run.
- One vector per description was measured useless for a 128-token model before the threshold was set; the piece index replaced it.
