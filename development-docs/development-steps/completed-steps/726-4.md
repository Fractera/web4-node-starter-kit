## The measurement (primary sources, read 2026-11-12; `lib/money-day.cjs` names the pages)

- **OpenAI** — the API has NO balance endpoint. The organization's spend per day in USD is `GET /v1/organization/costs` (buckets of
  1 day) and only with an **Admin key** (`OPENAI_ADMIN_KEY`), not the project key the node calls models with. The Admin API also has
  spend limits and spend alerts (organization and project) — not used here.
  developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs
- **Exa** — the remaining prepaid balance in USD is `GET https://admin-api.exa.ai/team-management/credits` with a **service key**
  (`EXA_SERVICE_KEY`); the Team Management API is enabled per team on request to support@exa.ai; the balance may lag 5 minutes.
  exa.ai/docs/reference/team-management/get-team-credits.md
- The node knows no price list, so the burn is counted in CALLS and no sum is ever estimated from calls.

## What was done

- `lib/money-day.cjs`: `dayBurn` (today UTC from the ledger: no-spend / no-budget with the pace / within / will-cross at HH:MM /
  crossed at the n-th call / refusing — the provider already refuses for money), `probe` (Exa balance, OpenAI day's spend; no key →
  no call), the budgets `data/node/budgets.json` (outside git, atomic write, a bad id refused). The OpenAI admin query goes through the
  node's one reader and writes its ledger line as `openai-admin`, so it never counts into OpenAI's burn — `check:openai-calls` caught my
  first draft that called OpenAI without them.
- «Все подписки»: the Calls cell carries today's line and the «Бюджет» popover (shadcn Popover + InputGroup); «Проверить балансы» is the
  only moment the providers are asked (`?balances=1`); the Keys cell carries the answer with the billing link. Six columns kept.
- `npm run money -- --balances`.
