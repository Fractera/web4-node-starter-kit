## What was done
- `scripts/node-update.mjs` — stage `preflight` after `fetch`, before `backup`: a dry merge in `<realpath tmpdir>/fractera-dry-<sha>-<pid>`
  with the machine's identity; a conflict outside the node's own files → `refused` with `conflicts`, no backup; `--preflight` prints only
  `===NODE_UPDATE_PREFLIGHT=== {ok, conflicts, behind, updater}`, writes no state and wakes nobody.
- `POST /api/node/update {action: "preflight"}` (409 while an update runs) → stage 0 `--preflight`; the version bar
  (`origin-notice.client.tsx`) asks it once when the node is behind and says «Пробное слияние прошло: обновление пройдёт» or names the files.
- The launch page: `launch.mjs` `probe` runs this computer's stage 0 `--preflight` on a server that is behind, as the node's user, from a
  readable `/tmp` copy; the verdict is kept in `/root/.fractera/preflight.json`, shown by `state.sh` and beside the strategy.

## Proofs

   `preflight`, no backup folder, HEAD equal. Negative control: the clean node's real update goes past the preflight (stops at guards).

behind its synced fork, which it was not at the time — owed to the next node update.
