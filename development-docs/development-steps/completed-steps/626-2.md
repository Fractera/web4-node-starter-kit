## Mistakes
- `process.exit()` after the first inference aborts the process inside `onnxruntime-node` 1.21 on macOS (SIGABRT, exit 134, «mutex
  lock failed») — found when `test:embed` printed OK and still failed; dispose() and one thread do not help, a natural end of the loop
  does. Fixed where it happens: the tests end with `exitCode`; after the load SIGINT/SIGTERM end the process by that signal (the
  standalone server: `server exited rc=143`, no abort).
- The developer's model folder was first `data/model` inside the element — the build's broken-characters scanner walked the 17 MB
  tokenizer and failed the build; the fallback is now the user's cache, and on a node it is always `SERVICE_DATA_DIR/model`.
- `onnxruntime-node` 1.23 was tried as a way out of the abort — it does not load on macOS 12 at all (`std::to_chars` for double);
  1.21.0 stays, written in the code, the contract and the README.
- The first push of the element was refused: the template's `.github/workflows/three-os.yml` needs the token's `workflow` scope,
  which the `gh` token lacks. The element's history was rewritten without that file before anything reached GitHub (the README
  says how it comes back).
- The type check caught `handle()` of the status door declared with no parameter while its route passes one.
- The passport's first price (~0.6 GB) was the bare runtime of 626-1; the element process with its server holds ~0.8 GB — measured
  on the installed copy and corrected in `v0.1.1` (a tag is never moved).
