# 675-1 — The main agent comes back by itself after a good core build

**Repository:** Fractera/web4-node-starter-kit — code `51413e25`, this summary in the commit after it.

## The owner's word
2026-11-07, verbatim: «в самом идеальным вариантом было бы авто пробуждение после успешного завершения»; on doing it alone: «not call ,
not ask , to do to finish non stop , i am not is here», «start without me», «select best choosse».

## What was done
1. `lib/deploy/agent-return.cjs`: `noteBefore` asks the core BEFORE `closeLid` whether the main agent runs (`/api/agents/session`
   `action: "status"` reads the live sessions map) and writes `data/node/agent-return.json`; the previous core answers 400 to `status` —
   then the bridge's own `data/services/build/session-mode.json`. `wakeAfter` — `/api/agents/wake` `reason: "core-back"` with the node's
   line; `afterUpdate` — waits for `data/node/node-update.json` done (failed → the record dropped, 60 min at most).
2. `scripts/serve.mjs rebuild`: notes before `closeLid`, drops on both failures, wakes after `redrawCore`; inside a node update it starts
   `scripts/agent-return.mjs` outside the core's tree (`spawn-free`) — the update is not over at the build, and the `node-update.mjs`
   that delivers this step is the old one in memory.
3. `/api/agents/wake` `core-back`: only `build` (403 otherwise), confirmed, no `from` (the conversation stays the person's),
   `continueLast`; the kit bridge `wake` passes `continueLast` when the folder has a conversation (`claude --continue`).

## Proof
1. **Function over a fake core** (scratch script): running → noted, 1 wake `core-back` to `build`; asleep → not noted, 0 wakes
   (negative); failed update → 0 wakes, record gone (negative); done update → wake; core silent → not noted; the OLD core's 400 → the
   bridge's record (running → true, stopped → false).
2. **Live on the owner's node** (fork synced to `51413e25`, detached `node:update`): `logs/node-update.log` — «Главный агент работает —
   сборка его остановит…» (line 418), «Главный агент вернётся, когда обновление узла закончится удачно» (1418), `===NODE_UPDATE_DONE=== 1
   изменений форка, ядро b3e1c098`; `logs/agent-return.log` — `17:32:03 ===AGENT_RETURN=== главный агент вернулся (тот же разговор)`;
   `session-mode.json` running, opus, effort high, `at 17:32:03`; this very conversation went on from the node's line; the record gone.
