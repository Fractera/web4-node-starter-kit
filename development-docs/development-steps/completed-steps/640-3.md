## What was done
- `npm run skills -- hand <owner/repo@skill> --to <element> [--send] [--scripts-yes]` takes the skill from where it is: the node's own
  skills (the kept folder's fingerprint checked again), a judged suggestion (628), or the catalog.
- A catalog skill: «skip» or risks — refused with the reason; a licence outside the copyable list — «the card and its link only»;
  scripts — only with their own yes. Then Fractera's store at the commit `release.json` pins: the manifest, every file by raw link, each
  git blob against the manifest, the folder's fingerprint against the card; the source repository's LICENSE / NOTICE beside it when the
  folder has none. The store does not give it (down, missing, or a blob that does not match) → the original on GitHub by the catalog's
  own shallow, sparse fetch, taken only with the card's fingerprint. SOURCE.md names the copy's road, the licence, the marking, the
  person's yes.
- One place for every hand-over archive (`data/node/skills/hand/`), one door, one task text for the element's own agent (628's).
- Found on the way and fixed: on a node where nothing was ever judged the journal's folder did not exist — the hand-over failed
  (`ENOENT … suggested/ledger.jsonl`); one `ledger()` helper makes it.
