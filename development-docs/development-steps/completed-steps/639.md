## The rule (holds for messages written later too)
1. **The node's own messages.** A service message — «the agent is on», «already off», a command done, an answered question, the hint
   about the commands — disappears 30 s after it is sent. A result, a question still waiting for the person and a trouble that needs
   their action stay; a waiting question disappears when it is answered, when a newer one replaces it, or when its session closes.
2. **The agent's replies.** In one turn — from a message of the person or of the node to the end of the answer — only the LAST reply in
   a chat stays: the summary. Each earlier reply of that turn disappears 30 s after a later one is sent; a reply with files always stays.
3. **The guard.** A line that sends a Telegram `sendMessage` without «639: остаётся» / «639: исчезает» fails the build.
Kept by design: the notices of the core's notice door (⏰ 🟢 ⚙️, 636-8), the A2A pairs «asks / answers» (408-5), the person's own
messages.
