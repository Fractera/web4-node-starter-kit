## What was done
1. `/api/agents/session` `status` returns every live session (`key`, `byPerson`).
2. `lib/deploy/agent-return.cjs` records them all before `closeLid`; after a good build wakes the element agents first (`core-back`,
   `from: node` when the node had born the session), then the main agent with who came back, who did not (memory) and which `--work`
   sessions were not continued (one folder has one «last conversation», `--continue` would take the wrong one).
3. `/api/agents/wake` `core-back` accepts only a service the build recorded (`data/node/agent-return.json`), any other — 403.
4. Skill `.claude/skills/core-build-return` (what the build does to the agents, what the main agent does before and after, the price);
   the kit README names it.

## Proof
1. **Fake core** (scratch script): order `blocks(from node) > graph > build`; `graph` refused (memory) named in the main line; `root--work`
   named, not woken; the record gone; an unlisted service refused by `listed` (negative); 675-1's cases still pass.
2. **Live on the owner's node**, the core `9bfcd6e9` (delivered by the update, CI green), `blocks` agent woken, then a detached «Deploy
   core» build (`core-deploy.mjs`): `logs/core-deploy.log` line 3 «Работают агенты: build, blocks — сборка их остановит…», line 981
   `===AGENT_RETURN=== главный: вернулся · элементы вернулись: blocks · не вернулись: — · рабочие сессии: —`; `core-deploy.json` done
   18:39:19; `data/services/blocks/session-mode.json` running, at 18:39:19; this conversation went on with the node's line naming
   `blocks`. The test agent closed after (`npm run close -- blocks`).
   Negative of the live plane: the update before it (core `b3e1c098` had no `sessions` in `status`) returned only the main agent —
   `18:35:15 … элементы вернулись: —`.
