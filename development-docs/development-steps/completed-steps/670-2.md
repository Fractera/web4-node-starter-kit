# 670-2 — A neighbour's job wakes the element's worker, naming which of its agents, and its «done» brings the report back

**Repository:** Fractera/web4-node-starter-kit — the commit of this summary (`git log -- development-docs/development-steps/completed-steps/670-2.md`).

## What was done and how
- `scripts/main-agent-cli.mjs` `task`: `--work` sends the text with «Working process:» — the bridge starts (or pastes into) `<id>--work`
  for an element with skill groups (552-4), the one session otherwise; `--skill <id>` is checked against the element's own skills and
  the template's shared frame from its self-description and opens the text with «skill <id> —»; `--skill` without `--work` is refused;
  `--dry` prints the session and the text and wakes nothing; the wake reason is `main-agent-job` (the door's consent rules unchanged:
  a Telegram question for an element with a bot unless it is led by the main agent).
- **A second hole, found by reading and closed here:** `lib/agent-kit/mount.cjs` woke the main agent only on a supervised BUILDER's
  «done»; a worker's «done» closed its session silently (552-4), so the report of a job would lie unread. New `lib/web4-items/jobs.cjs`:
  `task --work` sets a job record (`data/node/jobs-by-main.json`, outside git); that session's «done» takes it once in `mount.cjs` and
  wakes the main agent: «рабочий процесс элемента <id> закончил твоё поручение «…» — npm run state -- <id>». An event, never a timer; a
  record older than a day wakes nobody; a session already reported by supervision is not woken twice.
- Skills: `route-to-element` (a job → `--work [--skill]`, a code change → the builder), `ask-element` (a check → `--work`, a check of
  code or a build → the builder; the one-check lead is ended with `supervise <id> off`).

## Proof 1 — the command (workshop, real passports), verbatim
```
> task root --work --skill help-desk --dry "Summarize the three questions visitors asked most this week"
===TASK_DRY=== root → session root--work
Working process: skill help-desk — Summarize the three questions visitors asked most this week
> task root --skill help-desk --dry x
===MAIN_AGENT_FAIL=== --skill names which of the element's agents does a job — use it with --work
> task root --work --skill no-such --dry x
===MAIN_AGENT_FAIL=== root has no skill «no-such» — its own: help-desk; the shared frame: catalog-contribute, catalog-find, catalog-get, current-user, follow-settings, redraw-pages, site-shell (npm run card -- root)
> task root --dry "Rebuild the footer"            ← negative control: the old path is unchanged
===TASK_DRY=== root → session root
Build process: Rebuild the footer
> task data --work --dry "Count the rows of the deploy journal"
===TASK_DRY=== data → session data--work
Working process: Count the rows of the deploy journal
```
