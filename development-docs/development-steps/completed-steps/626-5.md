## Where it lives
`Fractera/fractera-graph-lightrag-starter` `6256212`, tag **`v1.2.0`**; the core pins it (the commit of this summary).

## What was done
- `services/graph/graph.py`: LightRAG's `embedding_func` calls the node's `embeddings` (`POST /api/embed`, up to 256 texts a call,
  `X-Node-Key` = the shared `SETTINGS_SECRET`, `EMBEDDINGS_URL` by the installer's neighbour rule) instead of OpenAI
  `text-embedding-3-small`; the model and its size are asked from `GET /api/embed-status` at every run. At the first run with another
  model the whole `lightrag/` and `spaces/` are set aside (`<name>.<old model>-<date>/`, under the lock, nothing deleted; no record —
  OpenAI) and `<SERVICE_DATA_DIR>/embed-model.json` records the new one. `max_token_size` stays 8192 on purpose: LightRAG reads it as the
  limit for summarizing descriptions, and a smaller one would make it call the language model this element does not have. `keyFound`
  is gone; `status` names `embedModel`, `embedDims` and `embeddings { model, dims, ready }` or the reason; a failure of `embeddings` is
  `embeddings_unavailable`.
- `lib/graph/run.mjs`: `embeddings_unavailable` → 503; `no_key`/`key_refused` gone. `graph-status` and its test, the admin search widget
  (one message «the node's embeddings element does not answer», en + ru), `.env.example` (`EMBEDDINGS_URL`), README («Using the graph»,
  the refusals, «Proven by»), the A2A card's sample.

## Proof

a data folder holding a graph of the pre-626 layout (`lightrag/` and `spaces/memory/` with 1536-number files):
1. **Door of the README's example:** insert «Pricing page» / «Stripe Checkout» → `{"ok": true, "chunks": 1, "entities": 2,
   "relationships": 1, "llmCalls": 0, "embedCalls": 3, "embedTexts": 4}`; query «How does the site take payments?» (mix, the keywords) →
   `found true`, entities Stripe Checkout and Pricing page, 1 relationship, 1 chunk, `llmCalls 0`, origin node; `status` →
   `"embedModel": "paraphrase-multilingual-MiniLM-L12-v2", "embedDims": 384, "embeddings": {…, "ready": true}`.
   Negative control: «Fix a leaking kitchen faucet» with `threshold: 0.5` → `found: false` («No relevant document chunks found.»); the
   right question with the same threshold → found.
2. **Files:** `lightrag.openai-2026-11-03/` and `spaces.openai-2026-11-03/` hold every old file with the same sha256 (3 of 3); the new
   `lightrag/vdb_entities.json` — `embedding_dim 384`, 2 vectors; `embed-model.json` — MiniLM-L12, 384.
   Negative control: `embeddings` stopped → `{"ok": false, "error": "embeddings_unavailable", "detail": "the embeddings element did not
   answer: … Connection refused"}`, the door answers `503`, `status` still counts (2 entities, 1 relationship, 1 chunk) with
   `embeddings.ready false` and the reason.
   The element builds with every guard: `npm run build` → `===GRAPH_PYTHON_OK=== uv 0.12.23, python 3.12.15, lightrag-hku 1.5.7`, `RC=0`; `npm run test:graph-status` → `===TEST_GRAPH_STATUS_OK===` (with «says whether the node's embeddings element answers»).
