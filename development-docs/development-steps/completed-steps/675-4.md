# 675-4 — No «Start the agent» while the core is silent; the build view holds from the stop to the verdict

**Repository:** Fractera/web4-node-starter-kit — `562313c3`, `4e35fbde`, this summary in the commit after them.

## The owner's word
2026-11-07, verbatim: «когда я тебе дал задание а потом отошел подошел через минуту на браузере уже не было ничего кроме голубой кнопки
запустить агента. Нажатие на эту кнопку привело к тому что экран браузер полностью исчез и вместо него осталось иконка релод. … скажи ещё
ты это просто не делал ещё или ты это сделал но проверить ты это не можешь потому что тебя в этот момент нету».

## The cause — found by a watcher, not guessed
675-2 had been proven only with fake records while the core was alive. A watcher outside the core's tree (Playwright + the system Chrome,
scratchpad, not in git) held `/en/architect/build/terminal` (live) and `/blocks/terminal` (asleep) open through a real «Deploy core»
build, state + console + a shot every 8 s: 18:47:15–18:47:32 the build terminal showed «The terminal is asleep · The connection to the node
was lost · Start the agent» — the core stopped, the reader not up yet (`startReader` ran AFTER `closeLid`; pm2 stops take ~16 s).

## What was done
1. `scripts/serve.mjs rebuild` starts the build reader BEFORE `closeLid`.
2. `core-build-watch.client.tsx`: core and reader both silent → a build («The core does not answer — a build or a restart is under way»),
   never the start card; a bare build ends with the verdict of the record that covered the silent moment, and waits while that record
   still says running (the core answers before the build writes done — the agents come back first). 14 kit copies updated.

## Proof (three watcher runs on the owner's node)
1. **Before the fix** (core `ba4ed71c`'s predecessor, 18:47): 2 frames with the start button on the build terminal (negative control).
2. **The update that delivered it** (old page JS + the reader first, 19:00–19:04): 0 start frames; the build view from 19:00:32 to the end;
   the page reloaded into the returned agent.
3. **«Deploy core» with the new JS** (19:21–19:25, core `83fe64ea`): 0 start frames during the build (52 frames `offline` + `build running`),
   then `build done` «The core build has ended · The core is built and running» with «Close and start the agent» and «Close» (shot
   `build-56`), then the page reloaded into the returned agent. The run before the verdict fix ended «The core answers again» — the fix's
   negative control. The two `checking` frames after the reload are the page connecting to the returned agent (the button disabled).

## Mistakes
- I reported 675-2 «proven» with fake records only; the real path — the core down — was never seen. A proof that cannot see the core
  stopped is not a proof of a build view; the watcher is the instrument for it.
- My first answer to the owner offered no cause; the watcher found it in one build.

## Evolution of skills
`use-testing` already demands two planes; the missing plane here was «during the real event». Nothing added — the summary names the watcher.
