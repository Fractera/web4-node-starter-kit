# 623 — The outbound A2A guard lets links to files through (closed 2026-11-02)

The owner, verbatim: «почини стража A2A для ссылок на файлы».

## What was wrong
`lib/a2a/guard.mjs`, rule `secret`, pattern «long base64 mixing cases and digits»: a link to a file
(`https://github.com/Fractera/web4-node-starter-kit/blob/main/README.md`) is one 40+ run of letters, digits, «-» and «/» — refused as a
secret. Found in step 622; the old sample URL passed only because `fractera/web4` was short.

## What was done
Inside a link (a word starting with `scheme://` or `host.tld/`) the rule checks each part between «/» alone; outside a link — the whole
run, as before. Templates custom v0.3.151 (cfb4cf3), native v0.1.34 (56ecd7d), pinned; rolled out to 11 native elements and root
(core pins `6a2a7d3`, `87f6fb7`). lagrix — not rolled out: outside the template kinds, only by the owner's word.

## Proof
1. `node lib/a2a/guard.test.mjs` — new samples: link to a file with and without scheme → allow; token in a link's path → deny `secret`;
   key with «/» outside a link → deny `secret`; all passed in both templates and in each of the 12 elements.
2. Negative control: the same test file against the previous guard — `FAIL url with path`, `FAIL url without scheme, file path`;
   the two deny samples deny there too, so nothing got weaker.

## Limits
The CLI (`npm run a2a -- send`) reads the file directly — fixed now. The reply door and the executor are compiled into each element's
build: they use the fix after that element's next build (`npm run services:install -- --only <id>`). No live A2A message was sent:
a probe goes to the owner's Telegram.
