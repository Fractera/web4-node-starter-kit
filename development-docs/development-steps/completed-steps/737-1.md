## What was built

- `lib/hosting/hostnames.mjs` — `nodeNames({ root, domain })`: every public name of the node with its target (service and port, or a 301
  target) and its label at the registrar, in the tunnel activation's own layout (apex → `root`, else the core; `architect.` → core when
  `root` exists; `auth.` → auth; `<address>.` → every other installed element; an element's own domain — main address to the element,
  second names to the core's 301; `www.<zone>` optional, answered by nginx with 301). The zone: asked → `data/node/server.json` →
  `logs/domain.json`. `dnsRecords(table, ip)` — A records per zone with the `*` shortcut for the node's zone. `corePort` from
  `logs/runtime.json`.
- `scripts/server.mjs` (`npm run server -- names|dns`) — the first two verbs of the dedicated-server command; marked last lines
  `===SERVER_NAMES===`, `===SERVER_DNS===`.
- `scripts/hosting.test.mjs` (`npm run test:hosting`, inside `prebuild`).

## Proofs

1. `npm run test:hosting` — 11 passed: no domain → no names; the tunnel layout; **negative:** an element without a port and the data folder
   of a deleted element (`s3v6y` with a `domain.json`) never appear; no root → the apex to the core, no `architect.`; an own domain as the
   main address and as the second one; **negative:** a broken own domain is ignored; the server's domain wins over the tunnel's zone; the
   core port from `runtime.json`; DNS grouping with the shortcut only for the node's zone; host-name rules (IDN refused by the node's policy).
2. The live plane — this node's registry and data, read-only: `node scripts/server.mjs names --domain example.org --root
   /Users/romanbolshiyanov/web4-node-starter-kit` → 15 names (14 required + `www`): `example.org → root:24683`, `architect → core:24680`,
   `auth → auth:24681`, data, storage, vectors, embeddings, config, graph, cache, memory, stripe, s8y6x, bd5ln at their ports;
   without `--domain` → «no domain», 0 names (this node has none).
