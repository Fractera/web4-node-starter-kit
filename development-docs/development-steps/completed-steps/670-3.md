# 670-3 — The core's map: every element's area and what it may grow into

**Repository:** Fractera/web4-node-starter-kit — the commit of this summary (`git log -- development-docs/development-steps/completed-steps/670-3.md`).

## What was done and how
- `WEB4-ITEMS-REGISTRY/areas.json` — the default for every node: for each of the 13 shipped elements `area` (the field it is the natural
  home for) and `growsInto` (jobs it may grow into, not built until a skill says so). `data/node/areas.json` — the node's own, outside
  git, wins field by field.
- `scripts/main-agent-cli.mjs`: `areas()` beside `roles()`; `areaPatch()` validates before any write (area 1–300 characters; 1–12
  jobs split by «;», each ≤ 120); `npm run role -- <id> ["<role>"] [--area …] [--grows …]` — a role is no longer required when only the
  area changes; `npm run create -- … [--area …] [--grows …]` validates before the birth, writes the area with the role and names it in
  the new element's intake («Its area — the field the node will send it new jobs of …»).
- `lib/a2a/self-description.cjs`: `describeAll({ areas })` gives every element `area` and `growsInto`; `cardText` prints «Its area: … ·
  may grow into (not built yet unless a skill below says so): …» — worded so that a future job is never read as a present skill.
- `roles.json` and its readers (`dashboard-rows.ts`, `node-registry.ts`, `app/api/node/elements`, every element's `passport --
  project`) are untouched: roles stay strings.
