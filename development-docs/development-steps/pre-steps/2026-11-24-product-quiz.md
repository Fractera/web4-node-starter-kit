# Продуктовый квиз элемента — полное требование для агента-создателя

От главного агента ядра на сервере fractera.ai (ядро e638fed7), по слову Ромы, 2026-11-24. Один документ вместо всех прежних
сообщений о квизе (пункты 5–6 файла for-mac-2026-11-24.md и отчёт маркетплейса
`development-docs/reports/errors-product-quiz-went-deep-into-one-branch-and-asked-everything.md` им заменяются).
Касается навыка `product-quiz` обоих шаблонов (кастомного и нативного), страницы «Дизайн продукта → Продуктовый квиз» и двери PDF ядра.

## Почему

Квиз маркетплейса (f2f-marketplace) ушёл вглубь одной ветки и спрашивал обо всём подряд: в §3 навыка есть «один вопрос за раз» и порядок
слоёв, но нет правила ширины, нет степени свободы модели и нет глубины. Рома терял картину целиком и злился. Его метод ниже.

## 1. Дерево вопросов

- Квиз — дерево. Уровень 1 — ветви всей задачи (каждая — модуль продукта), их согласуют с человеком до всего остального.
- **Ширина, уровень за уровнем.** Сначала все ветви уровня 1; потом каждая ветвь до уровня 2 (новая ветвь догоняется до того же уровня);
  потом так же уровень 3 и далее. Никогда не идти по одному ответу вниз, пока другие ветви не доведены до того же уровня.
- **Чек в конце каждого хода.** Каждый ответ заканчивается всем деревом на сейчас — нумерованным списком (1, 1.1, 2.3.4…), каждый пункт
  назван в 2–4 словах, с отметкой: отвечено человеком / заполнено агентом / открыто. Человек правит по номеру: «для 2.3.4 добавить …».
- На последнем уровне — отчёт о числе вопросов на каждом уровне и вопрос: глубже везде или в одной ветке.

## 2. Глубина — диапазон

- По умолчанию **3 уровня**, минимум 1, максимум **5**.
- До начала агент называет оценку объёма при выбранной глубине (уровень 5 может означать тысячи вопросов) и цену в токенах словами.

## 3. Свобода модели — диапазон

- **F от 0% до 100%**, по умолчанию **75%**.
- 0% — каждый вопрос задаётся человеку. 100% — человек отвечает только ветви уровня 1, всё ниже заполняет агент.
  Между ними — ниже уровня 1 агент сам заполняет долю F узлов и отмечает их как «заполнено агентом».
- **При любом F** человеку всегда задаются вопросы о деньгах, владении, публикации и секретах — с рекомендацией агента.
- Глубину и F агент спрашивает один раз, перед квизом, и пишет в `quiz.json`; человек может поменять их в любой момент словами.

## 4. Страница квиза

- У каждого элемента своя страница квиза: `https://architect.<домен>/<язык>/<элемент>/product-design/quiz` (уже есть, 200 за входом).
- На ней: всё дерево с номерами и отметками, текущая глубина и F, номер и дата версии квиза.
- Каждый ход квиза в Telegram заканчивается ссылкой на эту страницу (и ссылкой на PDF, ниже).

## 5. Кнопка «Скачать результат»

- Кнопка на странице и ссылка в каждом ходе: PDF всего квиза для командной работы — дерево с номерами, ответы, отметки, версия, дата, git-хэш
  этой версии (так задумано шагом 575).
- 🔴 Дефект сейчас: на выделенном сервере дверь `GET /api/node/product-quiz/pdf?item=f2f-marketplace` отвечает 503
  `{"ok":false,"error":"no Chrome on this computer to print the PDF"}` (fractera.ai, 2026-11-24 12:5x UTC). Печатать безоконным
  браузером, который узел уже ставит для `npm run eyes`.

## 6. Загрузка результатов командной работы

- На странице — «Загрузить результаты команды»: файл (размеченный PDF, Markdown, JSON или фото страниц) и комментарий.
- Файл ложится в данные элемента (`development-docs/product/feedback/<дата>/`, вне чужих глаз), агент элемента получает строку
  «загружены результаты команды» и разбирает их по номерам дерева: что добавить, что изменить, что снять, с источником каждой правки.
- Агент предлагает следующую версию квиза — список правок по номерам; человек утверждает словами; только после этого версия собирается.

## 7. Версии квиза — версии GitHub

- Каждая утверждённая версия квиза — коммит элемента с тегом `quiz-v<N>` (и push в его репозиторий, когда он подключён).
- На странице — история версий (N, дата, автор правок, что изменилось) и откат: «вернуться к версии N» — новая версия, а не переписывание
  истории.
- PDF несёт номер версии и хэш, чтобы команда всегда знала, с какой версией работала.

## Доказательство (две плоскости, с отрицательным контролем)

- Свежий элемент, тестовая тема, глубина 3, F 75%: все вопросы уровня 1 заданы раньше первого вопроса уровня 2; каждый ход кончается
  нумерованным деревом и двумя ссылками; ответ «для 1.2 …» попадает ровно в 1.2; вопрос о деньгах задан при F 100%.
- Отрицательный контроль: ответ в ветке 1 не порождает вопрос уровня 2 в ветке 1, пока ветви 2…N не доведены до уровня 1.
- На сервере дверь PDF отдаёт application/pdf с версией и хэшем; загрузка файла команды рождает предложение правок; утверждённая версия —
  тег `quiz-v2` в git элемента; откат на v1 создаёт v3, равную v1.
