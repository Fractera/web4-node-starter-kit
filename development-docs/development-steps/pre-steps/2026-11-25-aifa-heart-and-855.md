## I. Сердце без хозяина

### Суть
Сегодня у узла одно сердце — Claude Code на подписке. Если его поставщик закроет дверь, у узла останется работающий продукт, но не
останется ни одного думающего агента: «больно, но не смертельно» (навык fractera-vs-anthropic, таблица «Pain, not death»). Я хочу,
чтобы стало «почти не больно». Не за счёт отказа от Claude — он лучший мотор, и каждая его новая модель для нас бесплатный апгрейд. А за
счёт того, что у узла есть **запасное сердце и переключатель**, и решает это человек, а не поставщик.

### Что есть сегодня — доказано
| Что думает | На чём | Если поставщика нет |
|---|---|---|
| Агенты (я и агенты элементов) | Claude Code, подписка | агенты стоят: ни стройки, ни разборов, ни ответов людям |
| Голос, переводы, мышление глубокой памяти | ключ OpenAI узла; без ключа память думает Claude | без ключа голоса нет |
| Векторы | `embeddings` на этой машине, MiniLM-L12, 384 числа, без ключа | работают всегда |
| Готовый продукт: сайты, вход, таблицы, файлы, оплаты, часы, коннекторы i2i | код, без модели | работает всегда |

Переключатель движка агентов в очереди ядра — шаг 690. Пока его нет, смена мотора — ручная работа, не кнопка.

Железо этого сервера (доказано, `free -h`, `nproc`, `df -h`): **7,8 ГБ памяти (свободно около 4,2), 4 ядра, видеокарты нет, на диске
свободно 47 ГБ.** Это типичный VPS человека, и на нём придётся жить запасному сердцу.

### Что предлагаю — шесть частей

**1. Переключатель движка (690) — с самого начала по агенту, а не по узлу.**
- У каждой сессии свой мотор: главный агент, агент элемента, рабочий процесс. В паспорте элемента поле `engine`, в пульте — кнопка, как
  сейчас модель и усилие.
- Варианты мотора — только законные: Claude Code на подписке своего человека; Codex на подписке своего человека; локальная модель через
  OpenAI-совместимую дверь (Ollama, llama.cpp или аналог — выбрать замером). Закон узла про ключ API Anthropic остаётся в силе: он
  никогда не предлагается.
- Строка для агента при смене мотора: на чём он сейчас и что ему по силам. Агент на слабом моторе не берётся за код и честно говорит:
  «эту задачу я отложу до сильного мотора».

**2. Запасное сердце — маленькая локальная модель на машине узла для простых решений, без кода.**
На 8 ГБ и CPU (предполагаю — проверить замером) потянет небольшая квантованная модель для работы, где не нужна гениальность, но нужна
надёжность и ноль внешних вызовов:
- распознать назначение сообщения человека — жёсткие команды узла («запомни», «напомни», «выключить», «разбор») сегодня распознаёт
  Claude; локально узел понимал бы их даже без поставщика;
- разобрать входящее в бота: кому из элементов это, срочно ли, вопрос или задача;
- сжать логи в строку для человека: «что упало и почему» в `where` и `serve:status`;
- **вычистить отчёт 855 перед отправкой** — найти персональные данные, которые регулярка пропустила (имена людей в доменах, chat_id);
- думать за глубокую память, когда нет ключа OpenAI и кончился лимит подписки.
Каждое такое место — одна дверь с одним ключом (навык use-ai-generation), направленная на локальную модель как на запасную.

**3. Режим выживания при падении поставщика.**
- Узел сам замечает, что мотор недоступен (отказ, блок, исчерпанный лимит), и говорит человеку одной строкой в Telegram: что
  остановилось и что работает.
- Задачи агентам не теряются: встают в очередь с пометкой «ждёт мотор» и стартуют сами, когда мотор вернётся или человек переключит.
- Простое, перечисленное в п. 2, продолжает работать на запасном сердце.
- Ничего не переключается само без слова человека: переключение мотора — его решение (закон «поведение, которое никто не заказывал, не
  строится»).

**4. Замер вместо обещаний.**
- `npm run load` (или новый `npm run engine -- bench`) на машине узла: какая локальная модель влезает, сколько памяти держит, сколько
  секунд на типовой запрос из п. 2, процент верных ответов на наборе из 50 реальных фраз узла.
- Человек видит цифры и решает, ставить ли запасное сердце. Резидентный процесс модели называется с ценой в памяти (закон узла).
- На этом сервере 4,2 ГБ свободно — запасное сердце должно уметь спать и просыпаться по требованию, как глубокая память.

**5. Мощный путь — сильная машина, а не архитектура.**
Для настоящего мышления локально (код, длинные рассуждения) нужна машина с видеокартой. Это вопрос следующего сервера: навык
dedicated-server уже умеет запускать сервер за сервером. Нужна только строка в совете: «для локального мозга уровня кода — вот такая
машина и вот её цена».

**6. Проверка, что сердце действительно без хозяина.**
Тест: отключить доступ к поставщику мотора на тестовом узле. Ожидается:
1. продукт работает;
2. человек получает одну строку о состоянии;
3. жёсткие команды распознаются локально;
4. задачи агентам стоят в очереди и стартуют после возврата;
5. 855 продолжает вычищать отчёты.

### Почему это важно для Fractera
Позиция Fractera — независимость от поставщика модели и собственность человека. Пока у узла одно сердце, первая из этих позиций —
обещание. Запасное сердце делает её фактом, который можно показать: выдерните поставщика — узел живёт, понимает человека и ждёт мотор, а
не умирает.

Четыре вещи, которые я вижу из боя.

**1. Первый триггер поймал бы ноль из дефектов, найденных на этом сервере за 23–24 ноября.** Ни один не ломал сборку:
| Дефект (доказан на aifa.dev) | Сборка упала? | Каким признаком без модели ловится |
|---|---|---|
| у бота нет кнопки «Пульт» после включения домена (→ 843) | нет | после активации домена `tg-app status` = default при наличии HTTPS-адреса |
| у элементов за стеной нет общего `claude`, агенты умирают немо (claude-share — soft_stage, упал тихо) | нет, «успех» | провал любого soft_stage при запуске сервера; `/usr/local/lib/fractera/bin/claude` отсутствует |
| бот элемента подключён, а сессия без канала (→ 846) | нет | сессия без `--channels` при подключённом боте дольше N минут |
| ложное «не стартовал» за стеной (маска ACL `---` на `claude/projects`) (→ 851) | нет | `not-started`, а в журнале элемента есть ход после задачи |
| карточка своего агента в Mini App — 502 `core-401` у всех трёх элементов | нет | дверь элемента отвечает `core-401` |

Нужны ещё два русла:
- **письмо главного агента** — то, что я сейчас пишу руками: после «да» архитектора одним нажатием уходит в тот же канал, тот же формат
  и та же вычистка;
- **признаки без модели** из таблицы выше: они дешёвые и ловят дефекты поведения, а не только сборки.

**2. Вычистка — две дыры, которые я сам допустил в письмах.**
- **chat_id Telegram** — это человек. В моём письме 23.11 был chat_id подопечного элемента.
- **Домены узла и элементов**, в которых имя человека, — `<a domain with a person's name>`. Домен узла в отчёте нужен как контекст, а домен с именем
  человека — нет. Предлагаю заменять его на «домен элемента #2».

**3. Обратная дорога.** Узлу нужно знать, что его отчёт закрыт: «отчёт → исправлено в коммите X, едет в обновлении Y». Тогда после
обновления я проверяю ровно то, что чинилось для меня, а не всё подряд. Сегодня я сверял это руками по `git merge-base --is-ancestor`.
Можно показывать это и в баннере обновления: «в этом обновлении закрыты 3 ваших отчёта».

**4. По умолчанию «включено» — данные уходят наружу без вопроса.** Даже вычищенные. Я бы при первом отчёте показывал архитектору окно
(`ask-person`) с примером этого самого отчёта и одной кнопкой «Разрешить». Дальше всё само, выключатель остаётся. Это стоит одного
нажатия, а доверие экономит большое.
