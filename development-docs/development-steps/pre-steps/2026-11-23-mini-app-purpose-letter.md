## 2. Решение Ромы (2026-11-23, 18:38 UTC)

**Назначение Telegram Mini App — личный пульт одного человека:**
1. удобная навигация между страницами проекта;
2. переход из подходящего раздела в чат, чтобы обсудить выбранную тему;
3. краткая статистика и итоги — аналитическая панель;
4. отслеживание задач по расписанию;
5. поиск — внутри своих элементов, по f2f marketplace Fractera, в будущем по Lagrix.

**Что можно развивать:** новые разделы, категории и пункты; больше аналитики; больше форм управления строительством: ввод ключа, переключатель модели и другие.

**Нельзя:** строить внутри Mini App альтернативу странице сайта, его мобильной версии или функции приложения. Действие человек совершает на настоящей странице проекта, по своей роли.

**Один Mini App — один человек.** В одном приложении может быть несколько Mini App, по одному на человека. Пример Ромы: в приложении Марины — Mini App Марины и Mini App её помощницы Дианы. Здесь это люди, а не элементы узла.

## 4. Предложение: семь частей с учётом расхода токенов

### 4.1. Закон одной строкой — в CLAUDE.md §6 и в запечатанной инструкции элемента (`npm run instruction:element`)
Черновик по-английски, как сама инструкция, примерно 75 токенов на сессию:
> A Telegram Mini App is one person's remote: navigation to the project's pages, a jump from a section to a chat on its topic, short statistics, scheduled tasks and search (own elements, Fractera's f2f marketplace, later Lagrix); it grows by sections, analytics and build-control forms (a key, the model, switches) and never copies a page, its mobile version or an app's function — the person acts on the real page by role.

### 4.2. Карточка поверхностей при старте сессии — кодом, не текстом
Узел дописывает её в файл подсказки сессии (`data/services/<id>/session/<id>.md`) или в строку SessionStart. 4–6 строк, 60–100 токенов, без модели:
```
Поверхности cmdfc «Diana»:
  файлы      — WEB4-ITEMS/user/cmdfc
  страницы   — публичных 4, по ролям 7  (npm run pages -- cmdfc)
  Mini App   — https://cmdfc.aifa.dev/tg · пунктов 9: nav 5 · chat 1 · stats 1 · schedule 1 · search 1
  бот        — @Cmdfc_messenger_h2a… · канал: есть · кнопка Mini App: 1 чат
```
Главному агенту — пульт и Mini App всех элементов, одной строкой на элемент.

### 4.3. Схема `menu.json` v2 — у каждого пункта свой вид
`kind ∈ {nav, chat, stats, schedule, search, control}`:
- у `nav` есть `href` (маршрут элемента) и `roles`;
- у `chat` есть `topic`;
- `stats`, `schedule`, `search` и `control` называют свою дверь-источник данных.

Неизвестный вид — пункт недействителен.

### 4.4. Сторож `check:tg-menu` в prebuild шаблона — ноль токенов
- `nav` ведёт на существующий маршрут, и его роли входят в доступ этого маршрута.
- В `tg/` нет экрана, который рисует содержимое страницы: только отрисовщики шести видов.
- Новый экран без вида — сборка падает.

Сначала только предупреждение на живых элементах, обязательная проверка — со следующего тега шаблона. Так ни один живой элемент не сломается.

### 4.5. `npm run pages -- <id>|--all` — команда главного агента без модели
- Страницы элемента с доступом (гость или роли) и рядом дерево его Mini App.
- Читается через двери элемента (как `/api/tg-menu`) и через новую дверь `/api/pages`, которая отдаёт маршруты из папок данных с доступом.
- Код элемента не читается никогда: папки элементов закрыты для агента ядра по закону.

### 4.6. Mini App на человека
Техническая основа уже есть:
- `setChatMenuButton` ставит кнопку на каждый приватный чат отдельно (Bot API), и узел уже делает так для каждого разрешённого чата (`lib/node/tg-menu.cjs`);
- `initData` называет человека, а подпись проверяется бэкендом бота — пульт уже так делает.

Значит, личный Mini App — это тот же `/tg`, отфильтрованный ролью этого человека в приложении, и своя кнопка у каждого допущенного.

Чего не хватает:
1. Связи «Telegram id ↔ аккаунт и роль в приложении». Сегодня `access.json` (`allowFrom`) — это только допуск в бота.
2. `/tg` закрыт ролью администратора элемента (778). Помощница с другой ролью его не откроет.

⚠️ **Граница правил Anthropic — заложить в дизайн сразу.**
- Навигация, статистика, расписание и поиск по роли — можно.
- Всё, что запускает Claude (чат с агентом, формы строительства), для второго человека — только на его собственной подписке Claude.
- Consumer Terms Anthropic (2025-10-08): «You may not share your Account login information … with anyone else». Страница Claude Code «Legal and compliance»: учётка Pro/Max не для обслуживания других пользователей, лимиты рассчитаны на обычное личное использование.
- Цена нарушения: предупреждение, ограничения, приостановка или закрытие аккаунта; платежи не возвращаются.
- Законный путь уже есть в узле: навык integrator и закон §4 «several people never share one hand — an element each». Работа помощницы с агентом идёт в её собственном элементе на её подписке. В приложении Марины у неё свой Mini App и своя роль.

## 5. Миграция

1. **Шаблон** (навык release-template). Новый тег: `menu.json` v2, сторож в режиме предупреждения, экраны шести видов, имя из паспорта. Элементы получают его кнопкой «Обновить». У тех, чей `tg/` рисует содержимое, в документах разработки появляется шаг миграции: их агент превращает экраны в ссылки `nav` или в один из пяти видов.
2. **Ядро.** Строка закона, карточка поверхностей, `npm run pages`, исправление my-agent, имя элемента в `telegram.cjs`. Одна сборка (навык before-a-build). Случаи: домашний компьютер; сервер со стеной; элемент с ботом и без бота; два человека в одном приложении.
3. **Сервер.** Обновлять только тогда, когда живой бот элемента за стеной отвечает до и после (ваш закон 099d5aff).

## 6. Тесты: два доказательства из разных плоскостей

1. Пункт `nav` на несуществующий маршрут — сборка падает. Маршрут есть, но роли шире его доступа — падает.
2. Экран с содержимым страницы в `tg/` — падает. Карточка `stats` — проходит.
3. Карточка поверхностей есть в первой сессии свежего элемента и у главного агента, размер не больше 100 токенов.
4. `npm run pages -- cmdfc` показывает публичные страницы и страницы по ролям; публичные совпадают с `sitemap.xml`.
5. Два Telegram-пользователя с разными ролями видят разное меню. Человек без роли не видит ничего. `initData` чужого бота отвергается.
6. `/start t-<slug>` от допущенного человека — агент получает тему. От чужого — ничего: тема не открывает допуск.
7. Карточка своего агента у элемента за стеной — 200 и только свои данные. Ключ другого элемента — отказ.
